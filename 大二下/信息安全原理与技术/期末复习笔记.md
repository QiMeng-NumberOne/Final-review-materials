## 第一章：安全基础（Security Foundations）

### 1.1 核心概念

| 英文 | 中文 | 定义 |
|------|------|------|
| **Vulnerability** | 脆弱点/漏洞 | 系统、网络或应用程序中的缺陷或弱点，可被攻击者利用来破坏安全 |
| **Threat** | 威胁 | 任何可能对信息资产造成损害的事件或行为者（偶然如硬件故障，蓄意如网络攻击） |
| **Attack** | 攻击 | 利用漏洞实施的实际恶意行为 |
| **Countermeasure/Control** | 对策/控制 | 用于减少或消除漏洞、抵御威胁的安全措施 |

### 1.2 CIA三元组（CIA Triad）⭐

信息安全的基础模型，三大目标：

- **Confidentiality（机密性）**：确保数据只能被授权方访问
  - 破坏方式：截获/窃听（Interception）→ 未授权者获知部分/全部信息
- **Integrity（完整性）**：确保数据未被未授权篡改
  - 破坏方式：篡改（Modification）→ 信息被修改
- **Availability（可用性）**：确保系统与数据在需要时可正常使用
  - 破坏方式：中断（Interruption）→ DoS攻击、硬件故障导致服务不可用

### 1.3 四种攻击类型（必考）⭐⭐⭐

| 攻击类型 | 英文 | 含义 | 破坏目标 |
|----------|------|------|----------|
| **窃听** | Interception | 未经授权查看/获取信息 | 机密性 |
| **篡改** | Modification | 未经授权更改数据 | 完整性 |
| **伪造** | Fabrication | 未经授权创建/插入假数据 | 完整性 |
| **中断** | Interruption | 阻止合法用户访问资源 | 可用性 |

### 1.4 纵深防御（Defense in Depth / Layered Security）⭐

在不同层次（物理层、网络层、应用层等）部署多种安全措施，形成多层防护。即使某一层被突破，其他层仍然提供保护，从而增强整个系统的安全性。

### 1.5 MOM模型（Method-Opportunity-Motive）

攻击成功需要三个条件同时具备：
- **Method（方法）**：攻击手段（如钓鱼、恶意软件、DDoS）
- **Opportunity（时机）**：系统配置错误或未修补的漏洞
- **Motive（动机）**：经济利益、情报竞争、政治目的

> 安全措施的目标：破坏三者之一或多个，从而减少风险。

### 1.6 APT（Advanced Persistent Threat）

有资源充足的对手发起的隐蔽、长期、针对性网络攻击。目标通常为敏感数据或关键基础设施。需要持续监控、威胁情报和多层检测来防御。

## 第二章：访问控制与身份验证（Access Control & Authentication）

### 2.1 身份鉴别（Authentication）⭐

验证用户或进程身份的过程，三大因素：

| 因素 | 英文 | 示例 |
|------|------|------|
| 你知道什么 | Something you know | 密码、PIN码 |
| 你拥有什么 | Something you have | 智能卡、令牌、OTP |
| 你是什么 | Something you is | 指纹、面部、虹膜（生物特征） |

**多因素认证（MFA）**：结合两种或以上的验证方法。

**安全密码规则**：≥8位、包含字母+数字+特殊字符、不用生日和姓名、避免密码共用。

### 2.2 访问控制模型

| 模型 | 缩写 | 核心思想 |
|------|------|----------|
| **参考监控器** | Reference Monitor | 抽象概念，负责检查所有访问尝试，必须不可篡改、始终可用、可验证 |
| **访问控制目录** | Access Control Directory | 结构化数据存储，保存关于资源和用户访问权限的信息 |
| **访问控制矩阵** | Access Control Matrix | 表格结构，行=用户，列=资源，单元格=权限 |
| **访问控制列表** | ACL | 每个资源附加一个列表记录哪些主体有何种权限 |
| **面向程序的访问控制** | Procedure-Oriented | 通过特定程序/应用来控制访问权限 |
| **基于角色的访问控制** | RBAC | 权限分配给角色，用户通过角色继承权限 ⭐ |

## 第三章：密码学基础（Cryptography Fundamentals）

### 3.1 基本概念

| 术语 | 定义 |
|------|------|
| **Plaintext（明文）** | 未加密、可直接读取的原始数据 |
| **Ciphertext（密文）** | 加密后的输出，无密钥无法解读 |

### 3.2 对称加密 vs 非对称加密 ⭐⭐⭐（重点）

| 对比维度 | 对称加密（Symmetric） | 非对称加密（Asymmetric） |
|----------|----------------------|--------------------------|
| **密钥** | 同一密钥加解密 | 公钥加密 + 私钥解密 |
| **速度** | 快，适合大数据量 | 慢，算法复杂 |
| **密钥管理** | 每对通信方需共享密钥，管理复杂 | 只需维护一对密钥，公钥可自由分发 |
| **安全性** | 密钥需安全分发 | 公钥可公开，私钥保密 |
| **代表算法** | DES、AES | RSA |

### 3.3 流密码 vs 分组密码

| 类型 | 特点 | 代表 |
|------|------|------|
| **流密码（Stream Cipher）** | 按位/字节逐个加密，安全依赖密钥流的不可预测性 | RC4 |
| **分组密码（Block Cipher）** | 固定大小数据块加密（如128位），常用CBC、GCM模式 | DES、AES |

### 3.4 DES vs AES

| 对比 | DES | AES |
|------|-----|-----|
| **密钥长度** | 56位（过短） | 128/192/256位 |
| **数据块** | 64位 | 128位 |
| **安全性** | 已过时，易被暴力破解 | 当前标准，安全性强 |
| **现状** | 仅遗留兼容 | 广泛使用（磁盘加密、通信加密、VPN） |

## 第四章：软件与操作系统安全（Software & OS Security）

### 4.1 缓冲区溢出（Buffer Overflow）⭐⭐

**定义**：程序向缓冲区写入数据时超出边界，覆盖相邻内存，攻击者可利用此注入恶意代码或篡改控制流。

**危害**：覆盖程序的指令 → 攻击者获得程序执行权限；覆盖OS指令 → 获得OS执行权限

**防护措施**：
- 写入前检查长度、确认数组下标在限制范围内
- 仔细检查边界条件（±1错误）
- 限制输入为可接受字符数
- 限制程序权限
- 栈金丝雀（Canary Values）：在栈中放置特殊值检测溢出
- ASLR（地址空间布局随机化）

### 4.2 竞态条件（Race Condition）

**定义**：多进程/线程未同步访问共享资源，导致结果不可预测。攻击者可利用"检查到使用"之间的时间窗口提升权限或破坏数据。

**防护**：互斥锁（Mutex）、原子操作。

### 4.3 恶意代码（Malware）⭐⭐⭐

#### 三种主要类型对比（必考）

| 类型 | 病毒（Virus） | 蠕虫（Worm） | 特洛伊木马（Trojan Horse） |
|------|-------------|-------------|--------------------------|
| **是否独立** | 需要宿主程序 | 独立运行 | 伪装成合法软件 |
| **传播方式** | 附着在合法程序上，随宿主执行而复制 | 利用网络漏洞自动传播 | 诱骗用户下载/安装 |
| **是否需要用户交互** | 需要（用户执行宿主） | 不需要 | 需要（用户被骗安装） |
| **特点** | 自我复制，插入其他程序 | 自我复制，消耗带宽和资源 | 隐藏恶意功能，窃取数据/创建后门 |

**其他恶意代码**：
- **Rootkit**：深度植入OS内核，获取root权限并隐藏自身。检测需外部完整性检查工具。
- **预防措施**：使用可靠来源软件、杀毒软件、隔离环境测试、备份维护。

### 4.4 可信计算基（TCB）

系统中负责执行安全策略的所有硬件、固件和软件组件集合。TCB必须保持最小和可靠——任何组件被破坏都会导致整个系统安全失效。

### 4.5 操作系统层次化设计原则

1. **模块化（Modularity）**：易于维护和重用
2. **易于理解（Ease of Understanding）**：简化复杂性
3. **灵活性（Flexibility）**：易于扩展和替换
4. **可测试性（Testability）**：独立测试
5. **安全性（Security）**：安全隔离和访问控制
6. **协作性（Collaboration）**：并行开发

设计安全操作系统的原则：**简约设计、分层设计（分层信任）、内核化设计、引用监视器、可信系统**。

## 第五章：访问控制模型与数据安全

### 5.1 四种访问控制模型 ⭐⭐⭐（必考）

| 模型 | 缩写 | 核心特征 |
|------|------|----------|
| **自主访问控制** | DAC | 资源所有者决定谁可以访问，灵活但权限可被传播 |
| **强制访问控制** | MAC | 系统根据安全标签（"保密"/"绝密"）强制决策，用户不可覆盖 |
| **基于角色的访问控制** | RBAC | 权限分配给角色，用户通过角色继承，简化管理 |
| **基于属性的访问控制** | ABAC | 根据用户属性、资源属性、环境属性实时评估 |

### 5.2 审计（Auditing）

记录和审查安全相关事件（登录、数据访问），日志必须防篡改，通常集中到SIEM系统进行分析。

### 5.3 数据安全的四个维度

| 维度 | 含义 | 实现手段 |
|------|------|----------|
| **存储机密性** | 存储数据不被未授权访问 | 磁盘/文件加密、密钥管理、ACL |
| **传输机密性** | 传输中不被截获 | TLS、IPsec、VPN；前向保密（PFS） |
| **存储完整性** | 存储数据未被篡改 | 哈希校验、校验和、数据库日志 |
| **传输完整性** | 传输中未被篡改 | MAC（消息认证码）、数字签名、HMAC |

## 第六章：网络与无线安全（Network & Wireless Security）

### 6.1 网络为什么容易被截获？

1. **匿名性（Anonymity）**
2. **攻击点多（Many points of attack）**
3. **共享性（Sharing）**
4. **系统复杂性（System complexity）**
5. **未知边界（Unknown perimeter）**：一台主机可能是两个网络的节点
6. **未知路径（Unknown path）**：存在不可信路径

### 6.2 篡改/伪造的方式

| 方式 | 含义 |
|------|------|
| **Data corruption（数据损坏）** | 有意/无意、恶意/非恶意、定向/随机的数据损坏 |
| **Sequencing（顺序更改）** | 更改数据包到达顺序 |
| **Substitution（替代）** | 将数据流一部分替换为另一部分 |
| **Insertion（插入）** | 插入恶意代码 |
| **Replay（重放攻击）** | 拦截合法数据后在不适当时机重放，欺骗系统 |

### 6.3 WEP vs WPA ⭐⭐

| 对比 | WEP | WPA/WPA2 |
|------|-----|-----------|
| **加密算法** | RC4（有缺陷） | TKIP → AES-CCMP |
| **密钥** | 静态密钥，长度短 | 每数据包动态密钥（TKIP） |
| **IV** | 24位，易冲突 | 更长，不易冲突 |
| **完整性检查** | 有缺陷 | Michael算法 / AES |
| **鉴别** | 无有效鉴别 | 支持PSK、802.1X、证书 |
| **安全性** | 已过时，易被破解 | WPA2安全，应使用WPA2或更高 |
| **会话初始化** | 弱 | 四步握手，更健壮 |

### 6.4 DoS/DDoS攻击 ⭐⭐

**DoS（拒绝服务攻击）**：使系统无法向合法用户提供服务。

| 攻击类型 | 原理 |
|----------|------|
| **Ping Flood** | 发送大量ICMP Echo请求耗尽带宽 |
| **Smurf Attack** | 伪造源IP向广播地址发ICMP，所有主机回复被伪造IP |
| **Echo-Chargen** | 利用echo(端口7)和chargen(端口19)形成放大回路 |
| **Teardrop Attack** | 发送重叠/畸形IP分片导致重装时崩溃 |
| **DNS Spoofing** | 伪造DNS响应，将域名指向恶意IP |
| **Rerouting** | 操纵路由信息改变数据流向 |
| **Session Hijacking** | 窃取会话标识符接管已建立会话 |

**DDoS（分布式拒绝服务）**：利用僵尸网络（Botnet）多源同时攻击，更难防御。

- **僵尸网络（Botnet）**：由被感染且受控的主机组成的网络，用于DDoS、垃圾邮件等。

### 6.5 服务中断的原因

1. **路由中毒（Routing poisoning）**：配置不当导致路由信息错误
2. **过剩需求（Excessive Demand）**：超出带宽和处理能力
3. **元件失效（Component Failure）**：硬件/软件不可预测的故障

## 第七章：网络加密与边界防护

### 7.1 链路加密 vs 端到端加密

| 对比 | 链路加密（Link Encryption） | 端到端加密（End-to-End） |
|------|---------------------------|-------------------------|
| **加密范围** | 数据链路层两设备之间 | 发送端到接收端全程 |
| **中间节点** | 可解密查看 | 无法读取明文 |
| **保护范围** | 仅特定链路 | 整个传输路径 |

### 7.2 SSL/TLS

- **SSL（Secure Sockets Layer）**：遗留协议，在应用层与传输层之间提供加密，已过时
- **TLS（Transport Layer Security）**：SSL的后继，TLS 1.2/1.3广泛用于保护Web、邮件等通信

### 7.3 洋葱路由（Onion Routing）

通过多层加密和分步式中继实现匿名通信。每个中继只解密一层并转发到下一节点，无单一中继能同时知道源头和目的地。

### 7.4 VPN（虚拟专用网络）⭐⭐

通过公用网络建立临时、安全的加密隧道，使远程用户能安全访问私有网络。
- **优点**：网络隐私保护、突破地域限制、防黑客窃取信息
- **实现**：IPsec、SSL/TLS VPN

### 7.5 防火墙（Firewall）⭐⭐⭐

在受保护网络与不可信网络之间根据预设规则过滤通信流量的设备。

**防火墙三大特性**：
1. Always invoked（始终调用，无法规避）
2. Tamperproof（防篡改）
3. Small and simple enough for rigorous analysis（足够小和简单）

**防火墙类型**：

| 类型 | 工作层 | 特点 |
|------|--------|------|
| **包过滤网关（Packet Filtering Gateway）** | 网络层 | 检查包头（IP、端口、协议），不跟踪状态，高效但检查浅 |
| **状态检测防火墙（Stateful Inspection）** | 传输层 | 跟踪连接状态（TCP握手），阻止伪造/无效包 |
| **应用级网关/代理（Application-Level Gateway）** | 应用层 | 深度包检测，终端并重建会话，最安全但性能开销大 |
| **电路级网关（Circuit-Level Gateway）** | 会话层 | 监控TCP握手，验证会话合法性，不检查内容 |
| **守卫（Guard）** | — | 高保障安全设备，严格内容检查和数据净化 |
| **主机防火墙（Host-Based Firewall）** | 主机 | 单机防护，可针对应用设置规则 |

### 7.6 DMZ（非军事化区）

放置在内部网络与互联网之间的隔离网络区域，托管对外服务器（Web、邮件）。即使DMZ被攻破，攻击者也难以直接进入核心内网。

### 7.7 NAT（网络地址转换）

将内部私有IP映射为公共IP，隐藏内部拓扑，节约IPv4地址。提供一定程度安全性。

### 7.8 DLP（数据丢失防护）

监控并阻止敏感数据未经授权外发。检测指标：关键词、流量模式、编码/加密。

### 7.9 IDS vs IPS

| 对比 | IDS（入侵检测系统） | IPS（入侵防御系统） |
|------|-------------------|-------------------|
| **性质** | 被动 | 主动 |
| **行为** | 检测→告警 | 检测→自动阻止/缓解 |
| **部署** | 旁路（NIDS/HIDS） | 串联在网络中 |
| **典型用途** | 安全监控 | 实时防御关键基础设施 |

### 7.10 SIEM（安全信息和事件管理）

集中收集并关联来自防火墙、IDS/IPS、服务器等的日志和事件，实现实时监控、告警、历史分析、合规报告和取证调查。

## 第八章：隐私与数据库安全

### 8.1 隐私保护的主要对象

| 类型 | 说明 |
|------|------|
| **Identity（身份）** | 用户名、生物特征、证书等唯一标识 |
| **Finances（金融）** | 银行账户、信用卡、交易记录（受PCI DSS等监管） |
| **Health（健康）** | 病历、诊断（受HIPAA等法规约束） |
| **Biometrics（生物特征）** | 指纹、虹膜等，一旦泄露无法更换 |
| **Privileged Communications** | 律师-当事人、医生-病人等法律保护的通信 |
| **Location Data（位置）** | GPS、蜂窝、Wi-Fi信号获取的地理位置 |

### 8.2 数据库安全需求 ⭐⭐

| 需求 | 英文 | 含义 |
|------|------|------|
| **物理完整性** | Physical Integrity | 数据不受停电等问题影响，可重建被灾难破坏的数据库 |
| **逻辑完整性** | Logical Integrity | 保护数据库结构，修改一个域的值不影响其他域（ACID） |
| **元素完整性** | Element Integrity | 每个字段值正确有效（NOT NULL、CHECK约束） |
| **可审计性** | Auditability | 数据库日志可追踪谁访问/修改了什么 |
| **用户鉴别** | User Authentication | 对每名用户鉴别身份 |
| **访问控制** | Access Control | 用户只能访问被授权的数据 |
| **可用性** | Availability | 用户可访问授权数据 |

### 8.3 SQL注入（SQL Injection）⭐⭐

**定义**：将恶意SQL语句插入应用程序输入，使数据库执行未授权操作。

**防护**：
- 参数化查询（Parameterized Queries）
- 存储过程（Stored Procedures）
- 严格的输入验证

### 8.4 数据敏感性的来源

1. **固有敏感（Inherently sensitive）**：如密码、武器存放地点
2. **来自敏感来源（From a sensitive source）**：如保密线人的信息
3. **声明敏感（Declared sensitive）**：如机密文件
4. **敏感属性/记录的一部分**：如员工薪资
5. **与已披露信息相关的敏感性**：加密文件+密码的组合

## 第九章：数字签名（Digital Signatures）⭐

**定义**：使用发送方的私钥对数据进行哈希并加密，接收方使用发送方的公钥验证签名。

**三大特性**：
1. **完整性（Integrity）**：数据未被篡改
2. **不可否认性（Non-repudiation）**：签名者不能否认曾签名
3. **真实性（Authenticity）**：确认签名者身份

**应用场景**：软件分发、电子合同、电子交易等。

## 第十章：真题重点题型整理（2016 SIT182）

### 10.1 简答题高频考点

#### 1. 密码分析学（Cryptanalysis）
密码分析学是指在不拥有解密密钥的情况下，通过各种技术手段尝试破解加密消息、还原明文的过程。包括暴力破解、频率分析、已知明文攻击等方法。

#### 2. 社会工程 vs 反向社会工程

| 对比 | 社会工程（Social Engineering） | 反向社会工程（Reverse Social Engineering） |
|------|------------------------------|------------------------------------------|
| **发起方式** | 攻击者主动接触目标，利用心理操控获取信息 | 攻击者先制造问题，让目标主动联系攻击者求助 |
| **信任建立** | 攻击者伪装身份博取信任 | 目标主动寻求帮助，天然信任攻击者 |
| **典型场景** | 冒充IT支持打电话要密码 | 先制造系统故障，目标求助时获取信息 |

#### 3. 三种基本网络拓扑结构（6分）

| 拓扑类型 | 特点 | 优点 | 缺点 |
|----------|------|------|------|
| **星型（Star）** | 所有节点连到中心节点 | 易于管理，单点故障不影响其他节点 | 中心节点故障则全网瘫痪 |
| **总线型（Bus）** | 所有节点共享一条通信线路 | 布线简单，成本低 | 单点故障影响大，难排查 |
| **环型（Ring）** | 节点首尾相连成环 | 每个节点平等，传输路径固定 | 单点故障影响全网 |

#### 4. 四种访问管理方法（8分）⭐

| 方法 | 核心特征 |
|------|----------|
| **MAC（强制访问控制）** | 系统根据安全标签强制决策，用户无法覆盖。适用于军事/高安全环境 |
| **DAC（自主访问控制）** | 资源所有者决定访问权。灵活但权限可能扩散 |
| **RBAC（基于角色的访问控制）** | 权限分配给角色。最接近组织结构，简化大规模管理 |
| **Rule-Based（基于规则的访问控制）** | 根据预定义规则（如时间、IP）动态决定访问权 |

#### 5. 对称加密 vs 非对称加密（5分）⭐

| 对称加密 | 非对称加密 |
|----------|------------|
| 使用同一密钥加密和解密 | 使用公钥加密、私钥解密 |
| 速度快，适合大量数据 | 速度慢，算法复杂 |
| 密钥分发困难（每对通信方需共享密钥） | 密钥管理简化（公钥可公开分发） |
| 代表：DES、AES | 代表：RSA |
| 安全性依赖密钥保密 | 即使公钥泄露，私钥仍安全 |

#### 6. VPN（5分）

VPN（虚拟专用网络）是通过公共网络建立临时、安全连接的隧道技术。**优点**：加密网络流量保护隐私、突破地域限制、防止黑客窃取信息、提供安全远程访问。

#### 7. 定量 vs 定性风险管理（5分）

| 定量（Quantitative） | 定性（Qualitative） |
|---------------------|-------------------|
| 基于数据和数值分析 | 基于场景和描述评估 |
| 计算SLE、ALE、ARO等指标 | 使用高/中/低等分级 |
| 精确但需数据支持 | 快速但主观 |
| 公式：SLE = 资产 × 暴露因子（EF）；ALE = SLE × ARO | — |

### 10.2 选择题高频知识点

| 知识点 | 答案要点 |
|--------|----------|
| 密码第一步 | 创建有效且可管理的密码策略 |
| 最接近组织结构的访问控制模型 | RBAC |
| 多因素认证不包括 | What you calculate |
| 无法访问信息→损失 | Loss of availability |
| 非结构化威胁 | 不协调、非特定、持续时间短的攻击 |
| 替代密  不协调、非特定、持续时间短的攻码 | Substitution cipher |
| 密钥空间（Keyspace） | 所有可能的密钥值 |
| 蜜罐主要目的 | 帮助安全专业人员理解和防御威胁 |
| 三次握手顺序 | SYN, SYN/ACK, ACK |
| 浏览器中保证完美安全 | 没有保证完美安全 |
| 密码不应包含 | Dictionary words（字典单词） |
| 缓冲区溢出 | 发送超过预期的数据覆盖合法内存 |
| 内外网缓冲区 | DMZ |
| 双密钥加密 | Asymmetric encryption（非对称加密） |
| VPN用途 | 跨公共网络安全通信通道 |
| 监控流量+主动防御 | Active HIDS / IPS |
| 密钥交由可信第三方 | Key escrow（密钥托管） |
| 恶意代码自动发送给其他用户 | Worm（蠕虫） |
| 简单IP+端口规则 | Access control lists / Basic packet filtering |
| 无线安全问题 | 无法控制物理层流量 |
| chmod命令 | 修改文件读-写-执行属性 |
| 私钥签名→不能否认 | Nonrepudiation（不可否认性） |
| 风险管理目的 | 以经济有效方式降低风险至可接受水平 |
| ARO（年发生率）公式 | ALE = SLE × ARO |
| SEI风险管理步骤 | Identify, analyze, plan, track, control |
| 风险管理最常见 | 定性+定量结合 |
