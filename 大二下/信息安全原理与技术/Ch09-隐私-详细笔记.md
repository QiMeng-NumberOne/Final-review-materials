## 第一部分：什么是隐私

### 1.1 隐私的定义

> **Privacy** = 对你自己的信息的**控制权**。免于对个人事务的入侵。

隐私是一个人**控制其个人信息（包括活动元数据）披露**的权利或期望。

> 📍 *Slide 4*

### 1.2 大多数人认为私密的数据类型

| 类型 | 说明 |
|------|------|
| **Identity（身份）** | 用户名、身份证号、生物特征 |
| **Finances（金融）** | 银行账户、信用卡号、交易记录 |
| **Health（健康）** | 病历、诊断结果 |
| **Biometrics（生物特征）** | 指纹、虹膜扫描 |
| **Privileged communications（特权通信）** | 律师-当事人、医生-病人 |
| **Location data（位置数据）** | GPS、蜂窝、WiFi定位 |

**两个角色**：
- **Subject**：被数据描述的人或实体
- **Owner**：持有数据的人或实体

> 📍 *Slide 4*

### 1.3 计算机相关的隐私问题

| 问题 | 说明 |
|------|------|
| **数据收集** | 计算机存储的发展使得保存和操作海量记录成为可能 |
| **告知与同意** | 现代数据收集下，往往**不可能知道**什么被收集了 |
| **数据控制和所有权** | 一旦用户同意提供数据，数据就脱离其控制——可能被无限期持有或共享 |

> 📍 *Slide 5*

## 第二部分：间谍软件（Spyware）

> 间谍软件 = 旨在**监视用户、收集数据**的代码。

| 类型 | 说明 |
|------|------|
| **通用间谍软件（General spyware）** | 广告应用、身份盗窃 |
| **劫持者（Hijackers）** | 劫持现有程序用于不同目的，如重新配置文件共享软件以泄露敏感信息 |
| **广告软件（Adware）** | 在弹窗或主浏览器窗口中显示选定广告；通常以**误导方式**作为其他软件包的一部分安装 |

> 📍 *Slide 12*

## 第三部分：隐私保护法律

### 3.1 公平信息实践原则（Fair Information Practices）

| 原则 |
|------|
| 数据应**合法且公平**地获取 |
| 数据应与其**目的相关**、准确、完整且最新 |
| 数据使用目的应被**明确**，如不再需要应**销毁** |
| 目的外使用仅在**数据主体同意**或法律授权下进行 |
| 应建立防止数据丢失、腐化、破坏或误用的**保护程序** |
| 应能获取关于个人数据系统收集、存储、使用的**信息** |
| 数据主体通常有**访问和质疑**数据的权利 |
| 应指定**数据控制者**并对其合规负责 |

> 📍 *Slide 13*

### 3.2 美国隐私法律

| 法律 | 范围 |
|------|------|
| **1974 Privacy Act** | 体现上述大多数原则，但仅适用于美国**政府**收集的数据 |
| **HIPAA** | 医疗保健数据 |
| **GLBA** | 金融数据 |
| **COPPA** | 儿童网络访问 |
| **FERPA** | 学生记录 |

### 3.3 非美国隐私原则

- **欧洲隐私指令（1995）**：《通用数据保护条例》（GDPR）的前身
  - 适用于政府和企业
  - 对敏感数据额外保护
  - 严格限制数据跨境传输
  - 独立监督确保合规

### 3.4 中国隐私保护相关法律

| 法律 | 相关内容 |
|------|----------|
| 《宪法》第38条 | 公民的人格尊严不受侵犯 |
| 《民法通则》第101条 | 人格权包括**隐私权** |
| 《治安管理处罚法》第42条 | 偷窥、偷拍、窃听、散布他人隐私 |
| 《侵权责任法》第2条 | 明确列举**隐私权**为民事权益 |
| 《民事诉讼法》第134、156条 | 涉及个人隐私不公开审理 |
| 《刑事诉讼法》第52、150、183条 | 对个人隐私证据应当保密 |

## 第四部分：隐私增强技术（Privacy Enhancing Technologies）

### 4.1 最基本/最成功的隐私增强技术

**TLS**：随浏览器而来，无需配置，保护通信内容免受被动窃听和主动MITM攻击。

> 提供机密性的工具同时提供一定程度的隐私。

> 📍 *Slide 17*

### 4.2 推动HTTPS采用

- **2014**：HTTPS作为页面排名指标
- **2018年初**：Mozilla宣布新功能将要求HTTPS
- **2018年末**：新的Chrome HTTPS指示器
- 如今**92-93%**的Gmail消息已加密

## 第五部分：匿名性（Anonymity）⭐

### 5.1 什么是匿名性

> **Anonymity**（"无名称"）= 一个人在一组主体中**不可识别**。

| 属性 | 说明 |
|------|------|
| **Unlinkability（不可链接性）** | 操作与身份之间不可关联 |
| **Unobservability（不可观察性）** | 对手无法判断某人是否正在使用特定系统和/或协议 |

> 📍 *Slide 22*

### 5.2 为什么需要匿名性

| 原因 |
|------|
| 保护隐私：避免被广告公司追踪 |
| 查看敏感内容（医疗建议、破产信息） |
| 免受起诉：并非所有国家都保障言论自由 |

### 5.3 互联网匿名性很难

| 挑战 |
|------|
| 每个数据包中都有**源和目标IP地址** |
| ISP存储通信记录——执法部门可传票调取 |
| 无线流量可被轻易拦截 |
| Tier 1 AS和IXP已被国安机构攻破（NSA, GCHQ, "Five Eyes"） |

> 单靠自己几乎不可能实现匿名——你通常需要**帮助**（让其他人替你发）。

> 📍 *Slide 24-25*

## 第六部分：假名（Pseudonym）

| 类型 | 说明 |
|------|------|
| **全局唯一标识符** | 用户数据与全局唯一标识关联（如SSN、保险ID），不同实体可轻松共享与链接 |
| **局部假名+可信转换器** | 中央转换器从唯一标识生成独立的服务器局部标识符（假名），只有转换器能链接和转换 |

> 将假名与公钥一起认证（替代真实身份）是否足够用于数字签名？→ 否（可链接性问题）

## 第七部分：Tor（The Onion Router）⭐⭐

### 7.1 什么是Tor

> Tor是工作在**传输层**的成功的隐私增强技术，数百万活跃用户。  
> 正常情况下TCP连接会暴露你的IP地址，Tor允许**TCP连接而不暴露你的IP**。

> 📍 *Slide 34*

### 7.2 Tor的工作原理

Tor通过在多个"洋葱路由器"中使用公钥加密来**隧道传输**流量：

```
Alice → 入口节点 → 中间节点 → 出口节点 → 目标服务器
```

### 7.3 谁知道什么

| 角色 | 知道什么 |
|------|----------|
| **入口节点（Entry node）** | Alice在使用Tor，中间节点身份，但**不知道目的地** |
| **出口节点（Exit node）** | 某个Tor用户在连接目的地，但**不知道是哪个用户** |
| **目的地服务器** | 有Tor用户通过出口节点连接它 |

> ⚠️ Tor不提供出口与目的地之间的加密——**请使用HTTPS！**

> 📍 *Slide 35-36*

### 7.4 Tor提供的匿名性

- 对Tor用户**没有长期标识符**
- 如果Web服务器今天和明天各收到一次Tor连接 → **无法判断是否来自同一人**
- 但同一Tor节点**短时间内两次连接** → 更可能来自同一人

> 📍 *Slide 37*

### 7.5 Tor的挑战

| 攻击 | 防御 |
|------|------|
| 政府强迫一国的服务器运营者配合 | 使用不同**司法管辖区**的混合服务器 |
| 对手运营所有混合节点 | 拥有**大量**混合服务器（Tor现有约7000个） |
| 侧信道攻击——对手观察Alice何时发送和Bob何时接收 | 填充消息、引入显著延迟 |

> 📍 *Slide 38*

### 7.6 Guard Relays（守卫中继）

**问题**：如何防御对手创建大量洋葱路由器并进行入口出口的时序观察？

**解决方案**：限制初始连接使用的服务器为**受信节点的子集**：
- 具有长期且持续的在线时间
- 高带宽
- 由Tor社区**手动审核**

> Tor客户端选择**3个守卫中继**并持续使用**3个月**。

> 📍 *Slide 39*

### 7.7 Exit Nodes（出口节点）

- 中继必须**自选**成为出口节点
- **原因**：如果有人使用Tor做恶意/非法行为，警方追踪会指向**出口节点运营者**

> 📍 *Slide 40*

### 7.8 Tor Hidden Services（Tor隐藏服务）

> 想运行一个**不知道IP地址**的匿名服务？

Tor支持**隐藏服务**——在不披露IP或DNS名的情况下运行服务器。

**著名隐藏服务**：DuckDuckGo, TorChat, Wikileaks

> 📍 *Slide 41*

## 第八部分：机密计算（Confidential Computing）

### 8.1 定义

> 机密计算是一种在处理过程中将敏感数据**隔离在受保护环境中**的技术。

- 被处理数据的内容和处理技术仅对**授权代码**可访问
- 对其他任何事物**不可见、不可知**

### 8.2 实现模式

| 模式 | 说明 |
|------|------|
| **集中计算模式** | "数据可用不可见"——通过隐私泄露代价和概率的计算模型实现 |
| **协同计算模式** | "数据可用不可见"——**安全多方计算（Secure Multiparty Computation）**允许多个不相任的数据所有者协作计算并输出结果。（混淆电路、不经意传输、同态加密） |
| **"数据不动程序动"** | 数据不流通 → 算法程序流动。如**联邦学习（Federated Learning）**——将学习算法分散到各数据拥有方，只传回训练参数 |

## 第十部分：本章总结

1. 什么数据被认为是私密的**是主观的**
2. 隐私法律在不同司法管辖区**差异很大**
3. Cookie和Web beacon在网站间**追踪用户行为**
4. 间谍软件可用于追踪行为用于定向广告或更恶意的目的
5. 电子邮件**默认几乎没有隐私保护**
6. 新兴技术充满了隐私不确定性——技术问题和法律问题并存
