## 第一部分：身份认证（Authentication）

### 2.1 身份认证的基本问题

> *"How do you prove to someone that you are who you claim to be?"*

**Authentication（鉴别/身份认证）**：证明用户**就是其所声称的那个人**的行为。

> 任何具有访问控制的系统都必须解决这个问题。

| 概念 | 英文 | 含义 | 举例 |
|------|------|------|------|
| **标识** | Identification | 声明"我是谁"，强调**唯一性** | 姓名、身份证号、Email |
| **认证** | Authentication | **证明**"我就是我声称的那个人" | 输入密码、刷指纹 |

> 📍 *Slide 3-4*

---

### 2.2 三种通用认证方法 ⭐⭐⭐

| 方法 | 英文 | 说明 |
|------|------|------|
| **你知道什么** | Something you **know** | 密码、PIN码、安全问题 |
| **你是什么** | Something you **are** | 生物特征（指纹、面部、虹膜） |
| **你拥有什么** | Something you **have** | 令牌、智能卡、手机验证码 |

> 可以**组合使用**，即多因子认证（如：密码 + 短信验证码）。

| 攻击方式 | 英文 | 说明 |
|----------|------|------|

### 2.5 安全密码规则

```
✅ 避免密码共用（不同系统用不同密码）
✅ 8位或8位以上
✅ 包含字母、数字和特殊字符的组合
✅ 不用生日和姓名
```

### 2.6 口令空间（Password Space）⭐⭐

**定义**：所有可能口令的总数。

设字符集大小为 **S**，口令长度为 **n**，则：

$$\boxed{\text{口令空间} = S^n}$$

**乘法原理解释**：
- 第1位：有 S 种选法
- 第2位：有 S 种选法
- …
- 第n位：有 S 种选法
- 每位独立选择 → 总数为 S × S × … × S = Sⁿ

> 📍 *Slide 10-13*

---

### 2.7 密码存储（Password Storage）⭐⭐⭐

> **原则：密码绝不应以明文形式存储！**

课件提出三种存储方式的对比：

| 存储方式 | 安全性 | 问题 |
|----------|:---:|------|
| **明文（Clear text）** | ❌ | 数据库泄露→密码全部暴露 |
| **加密（Encrypted）** | ⚠️ | 服务器持有解密密钥，密钥泄露→密码全暴露；且服务器能从加密值反推明文 |
| **哈希（Hashed）** | ✅ | 服务器存储 H(password)，无法轻易从H反推密码 |

> 📍 *Slide 14-16*

---

### 2.8 密码哈希（Password Hashing）

**工作流程**：

```
注册时：
  用户输入密码 → 计算 H(password) → 存储哈希值到密码文件

登录时：
  用户输入密码 → 计算其哈希 → 与密码文件中的哈希值比较
  匹配 → 认证通过
  不匹配 → 拒绝
```

**关键特性**：
- 系统**不存储**实际密码！
- 系统自己也无法从哈希值轻易恢复密码（这如果是加密就做不到）

**哈希函数 H 的要求**：
| 属性 | 说明 |
|------|------|
| **单向性（One-way）** | 给定 H(password)，难以找到 password；除"逐个尝试"外没有更好算法 |
| **快速计算（Fast）** | 计算哈希值要足够快 |

> 📍 *Slide 17*

### 2.9 UNIX 密码系统 — 哈希 + 盐

**问题**：人类的密码**不是真正随机的**——人们喜欢用字典词、人名、宠物名。

| | 26个大写字母 + 26个小写字母 + 10个数字 + 32个标点 = **94个字符** |
|---|---|
| 8位密码的可能总数 | 94⁸ ≈ 6千万亿 ≈ 2⁵² |
| **但**：人类常用的密码 | ≈ 100万个常见词 ≈ 2²⁰ |

➡ 字典攻击成为可能！

> 📍 *Slide 18*

---

### 2.10 字典攻击（Dictionary Attack）

攻击者**预计算**字典中每个单词的哈希值 → 一旦获得密码文件 → **瞬时匹配**！

> 这只需要做**一次**（对所有密码文件通用），而且有成熟的密码猜测工具可用。

---

### 2.11 盐（Salt）⭐⭐⭐

**没有盐的情况下**：
- 相同密码 → 相同哈希值
- 攻击者预计算一个哈希表，可以用于**所有密码文件**
- 所有UNIX机器用相同的哈希函数！

**加入盐（Salt）后**：

```
存储：H(password + salt) + salt（salt明文存储）
```

| 对比 | 无盐 | 有盐 |
|------|------|------|
| 攻击者工作量 | 对所有字典词计算一次哈希，通用于所有密码条目 | 对**每个密码条目**都要重新计算所有字典词的哈希 |
| 相同密码 | 哈希值相同（一眼可见） | 哈希值不同（因为盐不同） |
| 12-bit随机盐 | — | 同一密码可有 2¹² = **4096** 种不同哈希值 |

**盐的作用**：使预计算的字典攻击失效——攻击者必须针对每个盐值重新计算。

### 2.12 Pepper（胡椒）

- **Pepper**：一个**不存储在密码文件中**的秘密盐值
- 即使密码文件泄露，由于不知道pepper，攻击者无法验证字典攻击的结果

> 📍 *Slide 20*

---

### 2.13 密码存储最佳实践总结

```
❌ 不要在服务器上存储明文密码
❌ 不要存储加密密码 + 加密密钥（密钥泄露=全暴露）

✅ 存储 H(password + random salt) 和 salt
   验证流程：
   1. 查哈希值和salt
   2. 计算 H(用户输入的密码 + salt)
   3. 比较，匹配则认证通过

⚠️ 即使如此，攻击者窃取数据库后仍可做字典攻击
    → 需要基于口令的认证密钥交换协议
```

## 第三部分：生物特征（Biometrics）— "Something You Are"

### 2.14 生物特征的问题

课件明确指出生物特征有七个问题：

| 问题 | 说明 |
|------|------|
| **侵入性（Intrusive）** | 用户可能不愿提供生物数据 |
| **昂贵（Expensive）** | 采集设备成本高 |
| **单点故障（Single point of failure）** | 指纹被盗 → 无法像密码一样"重置" |
| **采样误差（Sampling error）** | 同一个人不同时间的采样可能不同 |
| **误读（False readings）** | 误拒（假阴性）和误受（假阳性） |
| **速度（Speed）** | 识别速度可能不够快 |
| **伪造（Forgery）** | 指纹可被复制，面部可被照片欺骗 |

### 2.18 密码学的历史

#### 凯撒密码（Caesar Cipher / Shift Cipher）

> 字母按**固定偏移量**替换。

- 例：Shift 3 → A→D, B→E, C→F, …
- **密钥空间**：26种可能的偏移
- **攻击方式**：暴力穷举（只有26种）
- **ROT13**：Shift 13，加密和解密操作相同（对称）

> 📍 *Slide 31-32*

#### 替换密码（Substitution Cipher）

> Shift Cipher 的超集：每个字母被替换为**另一个任意字母**（加入密钥）。

- 例：A→Z, B→E, C→B, D→R, …
- **密钥空间**：26! ≈ **2⁸⁸**（巨大！）
- **攻击方式**：**频率分析（Frequency Analysis）**
  - 英语中最常见字母：e > t > a > o > i > n > s > h > r > …
  - 最常见字母组合（Trigrams）：the, and, tha, ent, ing
  - 最常见的大字母组合（Bigrams）：th(1.52%), he(1.28%), in(0.94%), er(0.94%), an(0.82%)…

> "State of the art" for thousands of years!  
> 📍 *Slide 33-34*

#### Enigma 密码机

- 使用**转子（Rotors）**（替换密码），每次按键后转子位置改变
- 密钥 = 转子的**初始设置**
- 密钥空间 = 26ⁿ（n为转子数）
- 图灵破解了Enigma → 二战转折点

> 📍 *Slide 35*

### 2.20 柯克霍夫原则（Kerckhoff's Principle）⭐⭐⭐

> *"The security of a cryptographic object should depend **only on the secrecy of the secret (private) key**."*
>
> *"Security should **not** depend on the secrecy of the **algorithm** itself."*

| 应该保密 | 不应该依赖 |
|----------|------------|
| **密钥（Key）** | 算法本身 |

**推论**：
- 使用**公开的、经过验证的算法** ✅
- **不要自己发明密码算法！！**（除非只想要加密效果，请使用经过验证的库！）
- 安全性的唯一保障是**密钥的随机性和保密性**

### 2.21 对称加密 vs 非对称加密 ⭐⭐⭐

这是 Ch02 最核心的概念之一。

| 对比 | 对称加密（Symmetric） | 非对称加密（Asymmetric） |
|------|----------------------|--------------------------|
| **密钥** | 双方共享同一个随机字符串 **K**（对称密钥） | 每方创建**公钥 pk** 和**私钥 sk** |
| **加密** | 用 K 加密，用 K 解密 | 用 pk 加密，用 sk 解密 |
| **速度** | 快 | 慢（算法复杂） |
| **密钥分发** | 需要安全的密钥分发通道 | 公钥可公开发布 |
| **理解难度** | 直观 | **难以理解，但是革命性的！** |
| **历史意义** | — | 发明者获得了**图灵奖** 🏆 |

> 📍 *Slide 39*

### 2.22 密码系统栈（The Crypto Stack）

| 层次 | 举例 | 说明 |
|------|------|------|
| **Primitives（原语）** | AES, DES, RSA, ElGamal, Elliptic Curve (ed25519) | 基础密码算法 |
| **Modes（模式）** | CBC, ECB, CTR, GCM | 分组密码的工作模式 |
| **Padding（填充）** | PKCS#7 等 | 处理数据长度非块大小的整数倍 |
| **Protocols（协议）** | TLS/SSL, SSH | 基于原语和模式构建的安全通信协议 |
| **Usage（应用）** | Browser security, Secure remote logins | 最终用户场景 |

## 第八部分：名词解释速记

| 术语 | 一句话答题模板 |
|------|---------------|
| **Authentication** | 证明用户**就是其所声称的那个人**的过程 |
| **Identification** | 声明身份（强调唯一性），如用户名、Email |
| **Dictionary Attack** | 用常见单词表预计算哈希，匹配密码文件的攻击 |
| **Salt** | 与密码一起哈希的**随机值**，使相同密码产生不同哈希值，阻止预计算攻击 |
| **Pepper** | **不存储在密码文件中**的秘密salt，额外保护层 |
| **Kerckhoff's Principle** | 密码系统的安全性应仅依赖于**密钥的保密性**，而非算法的保密性 |
| **Symmetric Encryption** | 双方共享同一密钥进行加密和解密 |
| **Asymmetric Encryption** | 使用公钥-私钥对，公钥加密、私钥解密 |
| **ROT13** | Shift 13的凯撒密码，加密和解密操作相同 |
| **Ciphertext** | 加密后的输出，无密钥无法解读 |
| **Keyspace** | 所有可能的密钥值集合，大小 = Sⁿ（S=字符集，n=长度） |
| **Rainbow Table** | 预计算的哈希-明文对照表，用于快速破解密码哈希 |
| **SSO** | 单点登录，一次认证访问多个系统 |
