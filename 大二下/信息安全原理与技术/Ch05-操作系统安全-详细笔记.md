## 一、操作系统基本概念

### 1.1 什么是操作系统

> OS是一组主管并控制计算机操作、运用和运行硬件/软件资源、提供公共服务来组织用户交互的相互关联的系统软件程序。

> **OS是所有系统资源的基本控制器 → 主要的攻击目标！**

> 📍 *Slide 1, 5*

### 1.2 OS的历史演进

| 阶段 | 特点 |
|------|------|
| **单用户系统，无OS** | 整台计算机同时只运行一个程序（浪费） |
| **单片机（Single Chip Microcomputer）** | 嵌入式设备 |
| **多道程序OS（Multiprogrammed OS / Monitors）** | 1970s, Unix（Bell Labs），多用户、调度、共享、并发 |
| **个人电脑（Personal Computers）** | 退步：重回单用户单程序 |
| **多任务回归（1990s）** | 带回早期共享计算机的所有经验教训 |

## 二、受保护的对象

OS需要保护以下资源：

| 对象 | 英文 | 说明 |
|------|------|------|
| **内存** | Memory | 进程间内存隔离 |
| **可共享I/O设备** | Sharable I/O devices | 磁盘等 |
| **串行可重用I/O设备** | Serially reusable I/O devices | 打印机等，需互斥 |
| **可共享程序/子过程** | Sharable programs/subprocedures | 共享库 |
| **网络** | Networks | 网络连接和通信 |
| **可共享数据** | Sharable data | 共享文件与数据库 |

> 📍 *Slide 6*

## 三、分离与共享（Separation and Sharing）

### 3.1 分离的方法

| 方法 | 说明 | 举例 |
|------|------|------|
| **物理分离（Physical）** | 不同进程使用不同物理对象 | 不同机器 |
| **时间分离（Temporal）** | 不同安全要求的进程在不同时间段执行 | 分时调度 |
| **逻辑分离（Logical）** | 程序不能访问许可域之外的对象 | VM |
| **密码分离（Cryptographic）** | 用加密保护各自数据 | 文件加密 |

### 3.2 支持分离/共享的方式

| 方式 | 说明 |
|------|------|
| **不保护（Do not protect）** | 分离时间运行时，OS不保护 |
| **隔离（Isolate）** | 并发时每个进程独立地址空间、文件等 |
| **全共享（Share all）或全私有（Share nothing）** | 公共数据 vs 私有数据 |
| **共享但限制访问（Share but limit access）** | RWX权限、逐用户检查 |

> 📍 *Slide 7*

## 四、内存保护机制

### 4.1 界地址寄存器（Fence Register）

- 最早的内存保护方式
- **重定位能力**：防止用户程序干涉OS
- **局限**：不能保护用户程序之间不相互干涉

> 📍 *Slide 9*

### 4.2 基址/范围寄存器（Base/Bounds Registers）

- 程序切换时地址变化 → **上下文切换（Context Switch）**
- 增加范围寄存器，标识每个进程的准确内存范围
- **两对基址/范围寄存器**：一对用于程序（指令），一对用于数据——实现指令与数据的**分离**

**问题**：连续性问题——完全共享或完全不共享，无法部分保护

> 📍 *Slide 10-11*

### 4.3 标记结构（Tagged Architecture）

- 解决基址/范围寄存器"全有或全无"的问题
- 额外的**比特位**用来表示该内存单元的访问权限
- 实现**细粒度**的访问控制

> 📍 *Slide 12*

### 4.4 分段（Segmentation）⭐

**定义**：程序被划分为**独立的、逻辑的片段**（如一个数组、一个过程）。

| 特征 | 说明 |
|------|------|
| **每段有独立访问权限** | 不同段不同权限 |
| **OS维护段表** | 记录每段及其实内存地址，翻译段调用 |
| **OS可移动段** | 段增长和收缩时灵活调整 |
| **段可移出内存** | 不使用时换出 |
| **每次地址引用必须经过OS** | 提供访问控制的机会——**细粒度** |

> 📍 *Slide 13-15*

### 4.5 分页（Paging）

- **固定大小**的片段（页，Pages）
- 配合分段使用：**段页式（Paged Segmentation）**

> 📍 *Slide 16-17*

## 五、安全OS设计原则 ⭐⭐⭐

### 5.1 四大核心原则

| 原则 | 说明 |
|------|------|
| **简约设计（Simplicity of design）** | OS本身很复杂，不必要的复杂度只会更难理解和保护 |
| **分层设计（Layered design）** | 实现**分层信任（Layered Trust）** |
| **分层信任** | 离中心越近的进程越可信；对关键OS功能严格访问控制，非重要功能放松 |
| **内核化设计（Kernelized Design）** | 安全内核负责整个OS的安全机制 |

> 📍 *Slide 19, 22*

### 5.2 分层结构的好处

- **识别关键部分**：层次结构允许我们识别非常关键的部分，认真分析其正确性
- **隔离（Isolation）**：将问题影响范围限制在问题发生的层及上层

> 📍 *Slide 23*

### 5.3 内核化设计详解

**内核（Kernel）**：OS中执行最底层功能的部分
- 同步（Synchronization）
- 进程间通信（Interprocess communication）
- 消息传递（Message passing）
- 中断处理（Interrupt handling）

**安全内核（Security Kernel）**：负责**实施整个OS的安全机制**
- 负责在硬件与系统其他部分之间提供**安全接口**

> 📍 *Slide 24*

## 六、虚拟化（Virtualization）

| 概念 | 说明 |
|------|------|
| **虚拟机（VM）** | OS给每个用户只呈现其应看到的资源 |
| **Hypervisor（VMM）** | 实现VM的软件，翻译VM和OS之间的访问请求，支持多OS同时运行 |
| **Honeypot（蜜罐）** | 引诱攻击者的VM——可被控制和监控 |
| **Digital Twin（数字孪生）** | 虚拟副本 |
| **沙箱（Sandbox）** | 受保护环境，程序可在其中运行而不危及OS（如Java） |

> 📍 *Slide 25*

---

## 七、模块化OS设计

- 模块（Modules）会被**更新/覆盖**
- → **模块之间不能互相完全信任**
- 第一个访问控制步骤是**实体认证（Entity Authentication）**
- 内核、分离、隔离和层次结构 = 许多可信系统模型的**基础**

> 📍 *Slide 26, 21-22*

---

## 八、参考监视器（Reference Monitor）

> 参考监视器是用于根据安全策略调解所有访问请求的核心组件。

**三个特性（必考）**：
1. **Always invoked**（始终调用，无法规避）
2. **Tamperproof**（防篡改）
3. **Small and simple enough for rigorous analysis**（足够小和简单）

> 📍 *Slide 27*

---

## 九、可信计算基（TCB）⭐

> TCB是可信系统中用于实施安全策略的**所有事物**的一个统称。

- 为增强系统安全策略的**所有必需元素**
- 由可信操作系统的某些部分组成，我们依靠这些部分来**正确地实施安全策略**

> 📍 *Slide 28*

---

## 十、可信系统（Trusted Systems）

### 10.1 定义

> 可信系统 = 不但达到了设计的安全需求，而且得到了**用户的信任**（用户相信设计方案、专家的评估、同行的意见）。

### 10.2 可信系统的三个特征

| 特征 | 说明 |
|------|------|
| **定义好的策略** | 详细说明它强制执行的安全品质 |
| **适当的措施和机制** | 可以正确执行安全 |
| **独立的安全评估** | 确保机制被正确选择和实现 |

> 📍 *Slide 29*

### 10.3 可信系统的其他特征

| 特征 | 说明 |
|------|------|
| **安全启动（Secure startup）** | 系统启动时最脆弱——大多数系统在加载安全功能前就加载了基本I/O |
| **可信路径（Trusted path）** | 用户能与OS**直接通信**的不可伪造连接 |
| **对象重用控制（Object reuse control）** | OS在重新分配内存前**清除**内存——防止残留数据被泄露（Cold boot attacks：内存转储攻击） |
| **审计（Audit）** | 可信系统追踪安全相关变更（新程序安装、OS修改）；审计日志必须防篡改和删除 |

> 📍 *Slide 30*

## 十一、Rootkit ⭐

> Rootkit是一种**恶意软件包**，它获得并利用**root状态**，或有效地成为**OS的一部分**。

**特征**：
- 竭尽全力**避免被发现**
- 如果被发现并部分删除 → 会**重新建立**自己
- 包括**拦截或修改**基本的OS功能

**检测**：需要**外部完整性检查工具**和**可信启动机制**（常规杀毒工具难以检测）

> 📍 *Slide 33*

## 十二、本章总结

1. OS从单用户单程序演进到多用户多程序
2. 需要OS保护的资源：内存、I/O设备、程序、网络
3. OS使用**分层和模块化**设计来简化结构、分离关键与非关键功能
4. 资源访问控制方式：虚拟化、分段、硬件内存保护、参考监视器
5. Rootkit是获得root状态或成为OS一部分的恶意软件包
