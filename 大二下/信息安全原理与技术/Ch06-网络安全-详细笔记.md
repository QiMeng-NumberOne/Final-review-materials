## 第一部分：网络基础

### 1.1 互联网是什么（"Nuts and Bolts"视角）

| 组成部分 | 说明 |
|----------|------|
| 数十亿连接的**计算设备** | Hosts = End Systems，运行网络应用 |
| **通信链路** | 光纤、铜线、无线电、卫星；传输速率 = bandwidth |
| **分组交换机** | 路由器和交换机，转发数据包（chunks of data） |

> 📍 *Slide 3*

### 1.2 互联网是什么（服务视角）

- 为应用提供服务的**基础设施**：Web、VoIP、邮件、游戏、电商、社交网络
- 提供**编程接口**让应用"连接"互联网

> 📍 *Slide 5*

### 1.3 什么是协议（Protocol）

> 协议定义了网络实体之间**消息的格式、顺序**，以及消息传输和接收时的**动作**。

| 人类协议 | 网络协议 |
|----------|----------|
| "几点了？" "2:00" | TCP连接请求/响应 |
| "我有一个问题" → 介绍 | HTTP请求 → 获取文件 |

> 📍 *Slide 6-7*

### 1.4 互联网协议栈（Internet Protocol Stack）⭐

```
  ┌──────────────┐
  │ Application  │  FTP, SMTP, HTTP — 支持网络应用
  ├──────────────┤
  │  Transport   │  TCP, UDP — 进程到进程的数据传输
  ├──────────────┤
  │   Network    │  IP, 路由协议 — 从源到目标的数据报路由
  ├──────────────┤
  │    Link      │  Ethernet, 802.11 (WiFi), PPP — 相邻网络设备间数据传送
  ├──────────────┤
  │  Physical    │  "在线路上的比特"
  └──────────────┘
```

> 为了方便管理互联网中的各种网络协议，设计者按**功能特性**以**分层**的方式组织协议。  
> **每一层都有自己的脆弱点！**

## 第四部分：为什么网络易被截获？⭐⭐

**解决方案**：**密码学（Cryptography）**是应对这一威胁最常用和最有用的控制手段。

## 第八部分：无线网络安全（WiFi Security）

### 8.1 无线网络的脆弱点

| 脆弱点 | 说明 |
|--------|------|
| **机密性** | 数据在开放环境中传输，他人可获知 |
| **完整性** | 数据可能被修改 |
| **可用性** | 信号可被干扰 |
| **未授权WiFi访问** | 未授权设备可尝试连接接入点 |
| **WiFi协议弱点** | 信标帧中的SSID、关联问题 |
| **Authentication** | 缺乏有效身份验证 |

> 📍 *Slide 30*

### 8.2 WEP（Wired Equivalent Privacy）

**工作原理**（⭐了解即可，WEP已淘汰）：
1. 客户端和AP有预共享密钥
2. AP发随机数给客户端，客户端用密钥加密后返回
3. AP用密钥解密并对比认证
4. 认证后，双方用密钥加密通信

```
Key Stream = RC4(v, k)
Message → XOR ← Key Stream → Cipher Text (PRF)
```

> 📍 *Slide 31-33*

### 8.3 WEP的弱点 ⭐⭐

| 弱点 | 说明 |
|------|------|
| **弱加密密钥** | 64或128位，其中24位用于IV，有效密钥仅40或104位 |
| **静态密钥** | 用户很少换密钥，一个密钥用数月 |
| **弱加密过程** | 40位密钥可暴力破解；RC4的缺陷使104位也易破解 |
| **弱加密算法** | RC4以奇怪方式使用，导致可解密大部分WEP通信 |
| **IV冲突** | 仅1600万种可能的IV值，以可预见模式循环 |
| **有缺陷的完整性检查** | Checksum不能应对恶意修改 |
| **无实体认证** | 只有机器到机器的认证，任何知道SSID和MAC的设备都可连接 |

> 📍 *Slide 34-35*

### 8.4 WPA/WPA2 ⭐⭐

| 优势 | 说明 |
|------|------|
| **非静态加密密钥** | 密钥层次结构：每会话生成新密钥，每包自动更换加密密钥 |
| **认证** | 支持密码、令牌或证书认证 |
| **强加密** | 支持AES（比RC4强得多） |
| **完整性保护** | 64位密码完整性检查（MAC） |
| **会话初始化** | 四步握手 → 认证密钥交换 → 两端各得独立的加密和完整性密钥 |
| **安全现状** | 有若干攻击，但效果很有限或需要弱密码 |

> 📍 *Slide 36-37*

## 第十部分：SSL/TLS ⭐⭐

### 10.1 发展历程

| 版本 | 年份 | 说明 |
|------|------|------|
| SSL 1.0 / 2.0 (Netscape) | 1994-1995 | 最早的安全传输协议 |
| SSL 3.0 (Netscape & MS PCT) | 1996 | 重大改进 |
| TLS 1.0 (=SSL 3.1) | 1999 | IETF标准 |
| TLS 1.1 | 2006 | 安全增强 |
| TLS 1.2 | 2008 | 当前广泛使用 |
| TLS 1.3 | 2018+ | **推荐版本** |

> 📍 *Slide 41*

### 10.2 SSL/TLS 安全连接特性

| 特性 | 说明 |
|------|------|
| **机密性** | 初始化连接后协商密钥，基于对称密码体制加密（如AES） |
| **对端实体认证** | 可用对称密码体制（长期共享密钥）或非对称密码体制（公钥） |
| **连接可靠** | 使用加密MAC算法进行消息完整性检查 |

> 📍 *Slide 42*

### 10.3 SSL/TLS 协议组成

> TLS不是单个协议，而是**两层协议**：

```
TLS Handshake Protocol（握手协议）
        ↓
TLS Record Protocol（记录协议）
        ↓
    可靠传输层
```

| 协议层 | 功能 |
|--------|------|
| **握手协议（Handshake Protocol）** | 协商密码参数；(相互)认证；建立会话密钥k（认证密钥交换） |
| **记录协议（Record Protocol）** | 使用会话密钥k进行**数据加密**和**认证** |

> 📍 *Slide 43-44*

### 10.4 握手协议详细流程

**功能**：
- 客户端和服务器**相互鉴别**对方身份（利用证书和认证机制）
- **协商安全参数**（加密和MAC算法、加密密钥等）
- 由一系列在客户和服务器间交换的**消息**组成
- 每个消息由3个字段组成：消息类型、消息长度、参数内容

**关键消息类型**：

| 消息 | 发送方 | 说明 |
|------|--------|------|
| hello_request | 服务器 | 可在任何时候向客户发送，启动握手 |
| client_hello | 客户端 | 首次连接时的第一条消息，包含支持的算法（Cipher Suites） |
| server_hello | 服务器 | 对client_hello的响应 |
| server_certificate | 服务器 | 服务器证书（X.509v3） |
| server_key_exchange | 服务器 | 服务器密钥交换 |
| certificate_request | 服务器 | 要求客户端证书 |
| server_hello_done | 服务器 | 服务器握手完成 |
| client_certificate | 客户端 | 客户证书 |
| client_key_exchange | 客户端 | 客户密钥交换 |
| certificate_verify | 客户端 | 验证客户证书 |
| finished | 双方 | 握手成功完成确认 |

> 📍 *Slide 49-50*

### 10.5 Cipher Suites（密码套件）

> 标准化的**算法选择**：密钥交换、签名、加密、哈希的组合。

例：`TLS_DHE_DSS_WITH_3DES_EDE_CBC_SHA`

**四组Cipher Suites**：
- Static Diffie-Hellman (TLS-DH)
- Ephemeral Diffie-Hellman (TLS-DHE)
- RSA encryption (TLS-RSA)
- Pre-Shared Key (TLS_PSK)

## 第十一部分：拒绝服务攻击（DoS）⭐⭐⭐

### 11.1 DoS 总体思路

> DoS = 试图破坏系统的**可用性**。

**两大类思路**：
1. 创建大量无用网络协议数据 → 网络拥塞 → 被攻击主机无法正常通信
2. 利用传输或应用协议的漏洞 → 反复发送畸形攻击数据 → 系统分配大量资源错误 → 主机挂起甚至崩溃

> 📍 *Slide 56-57*

### 11.2 四类 DoS 攻击

| 类型 | 英文 | 说明 |
|------|------|------|
| **容量耗尽攻击** | Volumetric attacks | 大量流量超过处理能力 |
| **基于应用的攻击** | Application-based attacks | 针对特定应用的弱点 |
| **通信中断** | Disabled communications | 中断或破坏网络通信 |
| **硬件/软件故障** | Hardware/software failure | 利用或者导致故障 |

> 📍 *Slide 56*

### 11.3 具体DoS攻击类型

| 攻击 | 机制 | 特点 |
|------|------|------|
| **Ping Flood** | 发送大量ICMP Echo请求耗尽带宽/主机资源 | 最基本的攻击 |
| **Smurf Attack** | 伪造源IP向广播地址发ICMP → 所有主机回复受害者 | **放大效应**（ECHO协议：接收到的信息原样返回） |
| **Echo-Chargen** | 利用echo(端口7)和chargen(端口19)形成**无限循环** | A和B之间建立无限循环；防御：心跳监控 |
| **Teardrop Attack** | 发送**无法正确重组**的IP分片 | 耗尽接收缓冲区 → 极端情况OS锁定；防御：心跳监控 |
| **DNS Spoofing** | 伪造DNS响应 → 重定向到恶意站点 | 无认证、无完整性；防御：应用安全通信协议 |
| **Session Hijacking** | 与接收方同步同时断开与发送方同步 | 攻击者接续TCP会话，发送方以为连接断开了 |

> 📍 *Slide 59-65, 94*

### 11.4 DDoS（分布式拒绝服务）

> 征召一支**已攻陷机器的军队（僵尸网络）**来攻击一个受害者。

- 选择受害者，让整支军队同时发动DoS攻击
- 通过**特洛伊木马**感染用户电脑，获取系统访问权

### 11.5 Botnet（僵尸网络）⭐

| 特征 | 说明 |
|------|------|
| **定义** | 运行恶意代码的机器网络，受远程控制 |
| **隐蔽** | 对宿主机器伤害小 → 难以被检测 |
| **多层结构** | 多个C&C节点 → 攻击者难以追溯 |
| **冗余** | 一个主控/C&C节点被关→僵尸可继续连接其他节点 |

> 📍 *Slide 66-67*

### 11.6 DoS/DDoS 防范策略 ⭐⭐

**课前预防**：

| 策略 | 措施 |
|------|------|
| 🛡️ **缩小攻击面** | 关闭不用的端口和服务；及时修补系统与应用 |
| ⚖️ **提升系统韧性** | 部署CDN/Anycast/负载均衡；关键业务支持扩容与故障切换 |
| 📈 **尽早发现异常** | 建立正常流量基线；监测请求量、连接数和错误率 |
| 分层过滤 | 恶意流量 → 边界防护 → WAF → CDN → ACL → 核心服务 |

**DDoS发生时处置流程**：

| 步骤 | 行动 |
|------|------|
| 🔍 **识别确认** | 攻击类型定位；受影响服务 |
| 🚦 **分流** | 联系ISP/CDN；牵引到清洗中心 |
| 🛡️ **过滤** | 限速、WAF、ACL阻断异常源 |
| ☁️ **保障** | 保护核心业务；降级非关键功能 |
| 📋 **复盘** | 更新规则；演练预案 |

> 核心思想：DDoS防护不是只"加服务器"，而是**分层过滤 + 弹性承载**。

## 第十二部分：防火墙（Firewall）⭐⭐⭐

### 12.1 定义

> 防火墙是在受保护（"内部"）网络与较不可信（"外部"）网络之间**过滤所有流量**的设备。

防火墙是**参考监视器（Reference Monitor）**的一个实例，应具备三大特性：
1. **Always invoked**（始终调用，无法规避）
2. **Tamperproof**（防篡改）
3. **Small and simple enough for rigorous analysis**（足够小和简单）

> 📍 *Slide 72*

### 12.2 六种防火墙类型

| 类型 | 工作层次 | 功能 |
|------|----------|------|
| **包过滤网关（Packet Filtering Gateway）** | 网络层 | 基于IP地址、端口、协议类型过滤 |
| **状态检测防火墙（Stateful Inspection）** | 传输层 | 跟踪连接状态（TCP握手），根据上下文判断 |
| **应用代理（Application Proxy）** | 应用层 | 模拟应用行为，过滤应用层请求，可缓存 |
| **电路级网关（Circuit-Level Gateway）** | 传输层 | 虚拟网关，实现VPN |
| **守卫（Guard）** | 应用层 | 复杂防火墙，可解释协议级数据；可限制邮件数、过滤文档关键词等 |
| **个人防火墙（Personal/Host-Based）** | 主机 | 运行在工作站上，可限制哪些应用可使用网络 |

> 📍 *Slide 72-81*

### 12.3 防火墙能做什么与不能做什么

| ✅ 能做的 | ❌ 不能做的 |
|-----------|-------------|
| 控制整个边界时保护环境 | 保护边界外的数据 |
| 作为安全策略的执行点 | 对进入内部的内容只做次要控制 |
| 正确配置并定期审查时提供防护 | 自动防御——需要持续维护 |
| 作为最显著的防护目标（也因此是攻击目标） | 替代内部安全控制 |

## 第十三部分：其他网络安全概念

### 13.1 VPN（虚拟专用网络）

> 在**公共网络**上提供**认证、机密性和完整性**的**安全隧道**，连接两个站点。

- 连接Office A到Office B，使它们看起来像一个无缝的私有网络
- 远程工作者可使用VPN连接到远程办公室

> 📍 *Slide 82-83*

### 13.2 DMZ（非军事化区）

- 放置在内外部网络之间的隔离网络段
- 托管对外服务服务器（Web、邮件）
- 即使被攻破也无法直接进入核心内网

> 📍 *Slide 96*

### 13.3 NAT（网络地址转换）

- 将内部私有IP地址映射为公共IP地址
- 隐藏内部网络拓扑
- 节约IPv4地址

> 📍 *Slide 97*

### 13.4 DLP（数据丢失防护）

| 方面 | 说明 |
|------|------|
| **功能** | 检测并可能阻止敏感数据发送到未授权的地方 |
| **实现方式** | Agent（安装在OS中的rootkit）、Guard |
| **检测指标** | 关键词、流量模式、编码/MAC |
| **效果** | 对防止**意外**事件最有效，恶意用户会找到规避方法 |

> 📍 *Slide 98*

### 13.5 洋葱路由（Onion Routing）

> 防止窃听者获知数据的**源、目的地或内容**。

**原理**：
- 使用非对称加密和多层中间主机
- 发送到最终目的地的中间主机**无法确定原始发送者**
- 从原始发送者接收消息的主机**无法确定最终目的地**

**应用**：帮助专制国家的用户自由与外界通信

> 📍 *Slide 93*

## 第十四部分：IDS / IPS ⭐⭐

### 14.1 IDS 的功能

IDS作为预防控制的**下一道防线**：

| 功能 |
|------|
| 监控用户和系统活动 |
| 审计系统配置中的脆弱点和错误配置 |
| 评估关键系统和数据文件的完整性 |
| 识别系统活动中的已知攻击模式 |
| 通过统计分析识别异常活动 |
| 管理审计轨迹并高亮策略违规 |
| 安装和操作陷阱（记录入侵者信息） |

> 📍 *Slide 87*

### 14.2 IDS的分类方式

| 分类维度 | 类型 |
|----------|------|
| **检测方法** | 基于签名（Signature-based）、启发式（Heuristic） |
| **位置** | 前端（Front end）、内部（Internal） |
| **范围** | 基于主机（HIDS）、基于网络（NIDS） |
| **能力** | 被动（Passive）→ IDS；主动（Active）→ **IPS**（入侵防御系统） |

> 📍 *Slide 90*

### 14.3 防火墙 vs IDS

| 防火墙 | IDS |
|--------|-----|
| 以**防御**为主 | 以**实时检测**为主 |
| 通过的数据不再操作 | 发现入侵行为即可做出反应 |
| — | 是对防火墙弱点的修补 |
| 可允许内部主机被外部访问 | 只监视和分析用户和系统活动 |

> 📍 *Slide 88*

### 14.4 SIEM（安全信息和事件管理）

- 汇集各用户访问日志（登录、操作、提交、下载、访问交换机等）
- 进行**存储、收集和分析**
- 发现潜在的安全风险和攻击行为

## 第十五部分：网络安全对策总结

| 层次 | 对策 |
|------|------|
| **用户访问安全** | 身份认证和访问控制 |
| **数据完整性** | 数据的完整和可用 |
| **数据机密性** | 信息的加密存储和传输 |
| **安全通信协议** | 在网络协议中使用加密技术、认证技术 |
| **安全通信协议基石** | 通信技术 + 密码技术（对称/非对称） |

## 本章总结（课件原文）

1. 网络面临**窃听、篡改、伪造、中断**四类攻击
2. WPA2相比WEP有**关键安全优势**
3. DoS攻击有多种形式，恶意的通常是**容量型**或**利用漏洞型**
4. 网络加密可通过专门工具实现——链路加密和端到端加密——如VPN、SSH、SSL/TLS
5. 防火墙类型多样，从基本IP功能到复杂应用层逻辑，可在网络和主机上使用
6. IDS有多种类型，各自检测不同种类攻击
