## 1. I/O 特点与设备分类

### 1.1 三种设备接口类型

| 类型 | 访问特征 | I/O 命令 | 典型设备 |
|------|------|------|------|
| **字符设备** | 以字节为单位，顺序访问 | `get()`, `put()` | 键盘、鼠标、串口 |
| **块设备** | 均匀数据块访问 | 原始I/O或文件系统接口 | 磁盘、磁带、光驱 |
| **网络设备** | 格式化报文交换 | `send()`, `receive()` | 以太网、WiFi、蓝牙 |

## 2. I/O 结构

### 2.1 CPU 与设备控制器

```
CPU ←→ 总线 ←→ 设备控制器 ←→ 设备

设备控制器是 CPU 和 I/O 设备之间的接口，包含：
  ● 数据寄存器（Data Register）
  ● 控制寄存器（Control Register）
  ● 状态寄存器（Status Register）
```

### 2.2 两种编址方式

| | 端口 I/O（独立编址） | 内存映射 I/O（统一编址） |
|------|:---:|:---:|
| **地址空间** | I/O 端口号，独立空间 | 映射到内存物理地址空间 |
| **访问指令** | 专用 I/O 指令（`in/out`） | 普通 `load/store` 指令 |
| **优点** | 不占内存地址 | 编程简单，指令丰富 |
| **缺点** | 需额外指令 | 占用内存地址空间 |

### 2.3 CPU 获知设备状态的两种方式

```
① 轮询（Polling）
   OS 定期检查设备状态寄存器
   简单，但频繁检查或不可预测时开销大

② 设备中断（Interrupt）
   设备完成操作时主动触发中断通知 CPU
   处理不可预测事件效果好
   开销相对较高（需保存/恢复上下文）
```

## 3. I/O 数据传输方式

### 3.1 三种方式对比

| | 程序控制 I/O (PIO) | 中断驱动 I/O | DMA |
|------|:---:|:---:|:---:|
| **数据传送** | CPU 逐字节搬运 | CPU 逐字节搬运 | 控制器直接访问内存 |
| **CPU 参与** | 全程占用 | 每次中断处理 | 仅设置和完成时参与 |
| **适用场景** | 简单小设备 | 低速设备 | **高吞吐量设备** |

### 3.2 DMA 完整读取步骤

```
① 设备驱动收到读取磁盘数据到内存地址 X 的请求
② 设备驱动控制磁盘控制器从磁盘读取数据
③ 磁盘控制器初始化 DMA 传送
④ 磁盘控制器传送数据到 DMA 控制器
⑤ DMA 控制器传送数据到内存地址 X（CPU 可执行其他任务！）
⑥ DMA 控制器完成数据传送后，产生中断，通知 CPU 传送完成
```

## 4. 同步与异步 I/O

```
        同步（阻塞）           异步（非阻塞）
        ──────────            ──────────

阻塞：   进程进入等待态          立即返回
        直到 I/O 完成           可能返回 0 字节

非阻塞： 立即返回               立即返回
        可能返回部分数据        完成后通知用户

        阻塞 I/O: "Wait"               "别叫我，等 I/O 完"
        非阻塞 I/O: "Don't Wait"        "先忙你的，有数据我叫你"
        异步 I/O: "Tell Me Later"       "完事了通知我"
```

## 5. I/O 请求生命周期

```
用户进程 ──→ 内核 I/O 子系统 ──→ 设备驱动 ──→ 中断处理例程 ──→ 硬件
                                                                      │
  ① 用户进程发起 read/write 系统调用                                   │
  ② 内核 I/O 子系统处理请求，向驱动发送命令                             │
  ③ 设备驱动配置控制器，等待中断                                       │
  ④ 设备控制器操作硬件                                                 │
  ⑤ 操作完成，产生中断                                                 │
  ⑥ 中断处理例程接收中断，保存结果，通知设备驱动                          │
  ⑦ 设备驱动与进程交换数据，返回完成结果或错误                            │
  ⑧ 系统调用返回，用户进程继续执行                                      │
```

## 6. 磁盘工作机制与性能参数

```
磁盘结构：

  磁道(track) — 盘片上一个同心圆
  扇区(sector) — 磁道上的一段弧
  柱面(cylinder) — 同一磁头位置上的所有磁道

三个时间参数：
  
  ① 寻道时间 — 磁头定位到期望磁道的时间
     → 最耗时，是调度的主要优化目标
  
  ② 旋转延迟 — 从期望扇区开始处到达目的地的时间
     平均旋转延迟 = 磁盘旋转一周时间的一半
  
  ③ 传输时间 — b ÷ (N × r)
     b = 传输比特数, N = 磁道比特数, r = 转速
```

## 7. 磁盘调度算法 ⭐

> 通过优化请求服务顺序来减少寻道时间。

### 7.1 FIFO（先来先服务）

```
按请求到达顺序服务
优点：公平 ✅
缺点：寻道距离大，性能接近随机
```

### 7.2 SSTF（最短寻道时间优先）

```
每次选择距离当前磁头最近的请求
优点：总寻道距离小 ✅
缺点：可能饥饿 ❌（远端的请求一直轮不到）
```

### 7.3 SCAN（电梯算法）

```
沿当前方向一路走到底，沿途服务，到尽头再反向
优点：更公平，两端都能服务到 ✅
缺点：刚服务过的区域要等磁头转一圈回来
```

### 7.4 C-SCAN（循环扫描）

```
只在一个方向上服务请求
到尽头后直接跳回另一端（跳回途中不服务）
优点：等待时间更均匀 ✅
```

### 7.5 C-LOOK

```
SCAN 的改进：不到尽头，到最后一个请求处就反向
避免扫过没有请求的空白区域
```

### 7.6 N-step-SCAN 与 FSCAN

```
磁头粘着（Arm Stickiness）问题：
  进程反复请求同一磁道 → 磁头一直停在那，其他请求饿死

N-step-SCAN：
  请求队列分成长度为 N 的子队列，FIFO 处理各子队列，SCAN 处理队内

FSCAN（双队列扫描）：
  N-step-SCAN 的简化版，只分两个队列交替
  新请求放入等待队列，当前队列 SCAN 处理完再切换
```

### 7.7 算法对比

| 算法 | 寻道优化 | 公平性 | 饥饿 | 粘着 |
|------|:---:|:---:|:---:|:---:|
| **FIFO** | 无 | 高 | 无 | 无 |
| **SSTF** | 好 | 低 | 可能 | 有 |
| **SCAN** | 好 | 中 | 无 | 有 |
| **C-SCAN** | 好 | 高 | 无 | 有 |
| **N-step-SCAN** | 好 | 高 | 无 | **解决** ✅ |
| **FSCAN** | 好 | 高 | 无 | **解决** ✅ |

## 8. 磁盘缓存

### 8.1 单缓存 vs 双缓存

```
单缓存 — 串行效率低：
  设备 → 缓存区 → 用户进程（读取时用户得等传送完）

双缓存 — 并行效率高：
  缓存区1 ← 设备传输  │  同时 ──→ 缓存区2 → 用户进程处理
  两个缓存区交替使用，传输和处理可以重叠
```

### 8.2 访问频率置换算法

```
问题：LFU 在一段密集访问后引用计数太高，无法反映当前情况

解法：三区域栈 + 引用计数

  栈顶 ┌──────────┐
  新区域 │ 访问: 计数│ ← 访问这里不增加计数！
       │不变       │
  中间区域│ 访问: 计数│ ← 访问这里计数+1（过渡区，避免新块立即被淘汰）
       │+1        │
  旧区域 │ 访问: 计数│ ← 访问这里计数+1（用 LFU 淘汰最少引用的）
  栈底 │+1        │
       └──────────┘

  新读入的数据块 → 栈顶，引用计数=1
  新区域不计数 → 避免密集访问的不良影响
  旧区域计数 → 长周期使用 LFU
  短周期 LRU + 长周期 LFU
```
