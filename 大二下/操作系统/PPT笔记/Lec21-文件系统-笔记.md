## 1. 文件系统概念

### 1.1 文件与文件系统

> **文件系统**是 OS 中管理**持久性数据**的子系统，提供数据存储和访问功能。
> **文件**是具有符号名，由字节序列构成的数据项集合。

```
文件系统的三大功能：

① 分配文件磁盘空间
   ├── 管理文件块（位置和顺序）
   ├── 管理空闲空间（位置）
   └── 分配算法（策略）

② 管理文件集合
   ├── 定位：文件及其内容在哪
   ├── 命名：通过名字找到文件
   └── 组织方式：分层目录树

③ 数据可靠和安全
   ├── 持久保存文件
   └── 避免系统崩溃、媒体错误、攻击等
```

### 1.2 文件的用户视图 vs 系统视图

```
用户视角（程序员看到的）：             系统视角（OS看到的）：
  字节序列的集合（UNIX风格）            数据块（block）的集合
  持久的数据结构                      数据块是逻辑存储单元
  getc() / putc()                   扇区是物理存储单元
                                     块大小 ≠ 扇区大小（块通常4KB）

用户 read() 1 字节的内部分解：
  ① OS 找到该字节所在的数据块（如4KB）
  ② 缓存整个 4KB 数据块到内存
  ③ 返回对应 1 字节给用户
  ④ 后续读同数据块时直接在缓存中命中
```

### 1.3 文件属性

```
文件头 = 文件系统元数据中的文件信息：

  名称、类型、位置、大小、保护
  创建者、创建时间、最近修改时间...
  文件在磁盘上的存储位置和顺序
```

### 1.4 文件描述符与打开文件表

> 进程访问文件前必须先"打开"：`f = open(name, flag);`

```
文件描述符 = 打开文件的标识（一个整数，如 0=stdin, 1=stdout, 2=stderr）

打开文件表分两层：

  ┌─────────────────────────────────────┐
  │         系统级打开文件表               │ ← 全局共享
  │  file1  file2  file3 ...            │
  └─────────────────────────────────────┘
         ↑         ↑
  ┌──────┴──┐ ┌───┴──────┐
  │进程A打开表│ │进程B打开表│              ← 每个进程一张
  │ fd=3→f1 │ │ fd=3→f2 │
  │ fd=4→f3 │ │ fd=4→f3 │
  └─────────┘ └──────────┘
```

**文件描述符包含的信息**：

```
● 文件指针：最近一次读写位置（每个进程独立维护）
● 文件打开计数：当前打开该文件的进程数
  → 计数归零 → 从打开文件表移除
  → 有文件被打开时，文件卷不能被卸载
● 文件的磁盘位置
● 访问权限：进程的文件访问模式
● 缓存数据访问信息
```

### 1.5 目录与分层结构

> 目录 = 一类**特殊的文件**，内容是 `<文件名, 指向文件的指针>`。

```
分层树型结构：

              root(/)
         /     |      \
       bin    usr     home
       / \    / \      / \
      ls cp  lib bin   jim avi

早期文件系统：扁平（只有一层目录）
现代文件系统：树型分层
```

**目录实现方式**：

| 方式 | 优点 | 缺点 |
|------|------|------|
| **线性列表** | 编程简单 | 搜索耗时（需遍历） |
| **哈希表** | 减少搜索时间 | 哈希冲突、固定大小 |

**典型目录操作**：搜索文件、创建文件、删除文件、遍历路径、列目录、重命名文件

**名字解析（路径遍历）**：

```
解析 "/bin/ls" 的完整过程：
  ① 读取根目录 "/" 的文件头（在磁盘固定位置）
  ② 读取根目录数据块 → 搜索 "bin" 项
  ③ 读取 bin 的文件头
  ④ 读取 bin 的数据块 → 搜索 "ls" 项
  ⑤ 读取 ls 的文件头 ✅

当前工作目录（PWD）：
  每个进程指向一个文件目录
  允许用相对路径代替绝对路径
  如 PWD="/bin"，直接 "ls" 即可
```

### 1.6 文件别名：软链接 vs 硬链接

```
软链接（Symbolic Link）：
  以"快捷方式"指向其他文件
  存储真实文件的逻辑名称
  ln -s target link
  删除原文件 → 软链接失效 ❌

硬链接（Hard Link）：
  多个目录项指向同一个 inode（同一个文件）
  ln target link
  链接数归零才真正删除文件
  不能跨文件系统，不能链接到目录（防止循环）

示例：
  /dict/count          ← 硬链接1
  /spell/count         ← 硬链接2，指向同一个inode
  /dict/w/list → /dict/all → /spell/words/list  ← 软链接链
```

**目录循环问题**：

```
/avi/book/avi/book/avi/book/... → 无限循环！

防止方法：
  ① 只允许到文件的链接，不允许到子目录的链接
  ② 限制路径可遍历的目录数量
  ③ 增加链接时用循环检测算法
```

### 1.7 文件访问模式

| 模式 | 说明 | 频率 |
|------|------|:--:|
| **顺序访问** | 按字节依次读取 | **最多** |
| **随机访问** | 从中间直接读写 | 较少但重要（如虚拟内存） |
| **索引访问** | 依据数据特征索引（数据库常见） | OS通常不完整提供 |

### 1.8 文件系统种类

```
磁盘文件系统       → FAT, NTFS, ext2/3, ISO9660
数据库文件系统     → WinFS（文件可寻址）
日志文件系统       → 记录文件修改/事件，支持崩溃恢复
网络/分布式文件系统 → NFS, SMB, AFS, GFS
特殊/虚拟文件系统
```

## 2. 虚拟文件系统（VFS）

> VFS 是对所有不同文件系统的**抽象层**，提供统一接口。

```
分层架构：

  ┌─────────────────────────┐
  │       应用程序           │
  ├─────────────────────────┤
  │   虚拟文件系统 (VFS)      │ ← 统一接口："读文件就是read()"
  │   文件/文件系统API        │
  ├────┬────┬────┬────┬─────┤
  │ext2│FAT │ISO │NFS │SMB  │ ← 各文件系统的驱动模块
  ├────┴────┴────┴────┴─────┤
  │   设备 I/O / 网络 I/O     │ ← 实际读写硬件
  └─────────────────────────┘

VFS 功能：
  ● 提供相同的文件和文件系统接口
  ● 管理所有文件和文件系统关联的数据结构
  ● 高效查询例程，遍历文件系统
  ● 与特定文件系统模块的交互
```

### 2.1 文件系统的物理组织

```
磁盘 → 分区（一组柱面的集合，最小化寻道时间）
    → 每个分区是一个逻辑独立磁盘
    → 文件卷：一个拥有完整文件系统实例的外存空间

文件系统的存储结构：
  卷（Volume）
  ┌──────────────┐
  │ Superblock    │ ← 卷控制块：文件系统详细信息（块数/块大小/空闲块...）
  ├──────────────┤
  │  inode 区     │ ← 文件控制块：每个文件一个（权限/大小/数据块位置...）
  ├──────────────┤
  │  目录数据块    │ ← 目录项（dentry）：<文件名, inode号>
  ├──────────────┤
  │  文件数据块    │ ← 实际文件内容
  └──────────────┘

三种关键数据结构：
  ① Superblock   → 文件系统挂载时进内存
  ② inode/vnode  → 文件被访问时进内存
  ③ dentry       → 遍历路径时进内存
```

### 2.2 文件系统挂载

```
文件系统需要先 挂载(mount) 才能被访问。

挂载前：                      挂载后：
/ (根)                       /
├── bin/                     ├── bin/
└── users/ (挂载点，空)        └── users/
                                   ├── sue/
                                   ├── jane/
                                   └── prog/
```

## 3. 文件缓存和打开文件

### 3.1 数据块缓存 vs 页缓存

```
数据块缓存（传统方式）：
  ● 数据块按需读入内存
  ● 预读：预先读取后面的数据块（空间局部性）
  ● 数据块使用后被缓存（假设会再次用到 → 时间局部性）
  ● 写操作可能被缓存和延迟写入

页缓存（现代OS主流 —— 联系 Lec8 虚拟存储！）：
  ● 文件数据块被映射成虚拟内存页
  ● read() → 内存访问 → 可能缺页
  ● write()→ 内存访问 → 标记脏页
  ● 统一缓存数据块和内存页

  read() → 页缓存 → 命中则直接返回 → 未命中则缺页调入
  write() → 页缓存 → 标记脏页 → 延迟写回磁盘
  
  问题：页置换算法需协调虚拟存储页和文件缓存页的数量
```

### 3.2 多种磁盘缓存位置

```
CPU → 内存 → 磁盘控制器 → 磁盘
              ↑
        内存中有：
        ├── 打开文件表
        ├── 数据块缓存
        └── 页缓存（虚拟内存子系统）

磁盘控制器 → 磁盘扇区缓存（硬件缓存）
```

### 3.3 文件锁

```
强制锁：根据锁状态强制拒绝不兼容的访问
劝告锁：进程自行检查锁状态后决定（不强制）
```

## 4. 文件分配

> 如何表示分配给一个文件数据块的**位置和顺序**。

### 4.1 连续分配

```
文件头指定起始块和长度：

┌───┬───┬───┬───┬───┬───┬───┐
│ 0 │ 1 │ 2 │ 3 │ 4 │ 5 │ 6 │
│ F1│ F1│ F1│F2 │F2 │ F3│空 │
└───┴───┴───┴───┴───┴───┴───┘
 F1: 起始=0, 长度=3

优点：顺序和随机访问都高效 ✅
缺点：
  ● 外部碎片！（跟 Lec5 连续内存分配同样的问题）
  ● 文件增长困难（预分配？按需？挪动？）
```

### 4.2 链式分配

```
文件头存首块指针和尾块指针。每块存下一块的指针。

文件头              块1      块2      块3
┌───┬───┐      ┌───┬───┐ ┌───┬───┐ ┌───┬───┐
│首块│尾块│──→  │数据│ ●─│→│数据│ ●─│→│数据│NUL│
└───┴───┘      └───┴───┘ └───┴───┘ └───┴───┘

优点：创建/增大/缩小容易，无碎片 ✅
缺点：
  ● 无法真正的随机访问 ❌（要顺着链走）
  ● 可靠性差 ❌（一个指针坏了，后面全丢）
```

### 4.3 索引分配

```
为每个文件创建一个索引块，存数据块指针列表。

文件头               索引块
┌─────────┐    ┌───┬───┬───┬───┐
│指向索引块│───→│块0│块1│块2│块3│
└─────────┘    └───┴───┴───┴───┘
                  ↓   ↓   ↓   ↓
                数据块...

优点：创建/增大/缩小容易，无碎片，支持直接访问 ✅
缺点：
  ● 小文件时，索引块本身是开销
  ● 大文件时，一个索引块放不下所有指针 → 需要多级索引！
```

### 4.4 UFS 多级索引分配 ⭐

> 文件头（inode）包含 **13 个指针**，分级管理。

```
inode 中的 13 个指针：

  指针 0~9  → 10个 直接数据块                    → 40KB (10×4KB)
  指针 10   → 1个 一级间接索引块                   → 4MB (1024×4KB)
               (每个索引项指向一个数据块)
  指针 11   → 1个 二级间接索引块                   → 4GB (1024²×4KB)
  指针 12   → 1个 三级间接索引块                   → 4TB (1024³×4KB)

假设：每块 4KB，每个指针 4字节 → 每索引块 = 1024 个指针

inode
┌─────┐
│ ptr0│────→ 数据块0
│ ... │
│ ptr9│────→ 数据块9
│ptr10│────→ ┌────┐
│ptr11│──┐  │索引 │ → ptr→数据块0 ... ptr→数据块1023 (一级间接)
│ptr12│┐ │  └────┘
└─────┘│ │  ┌──────────────┐
       │ └→│二级间接索引块  │ → ┌────┐ → ┌────┐
       │   └──────────────┘   │索引│   │索引│ → 数据块 (二级间接)
       │                      └────┘   └────┘
       │  ┌──────────────────────────────┐
       └→│三级间接索引块                   │ → 两层间接 → 数据块 (三级间接)
          └──────────────────────────────┘

效果：
  ● 小文件（≤40KB）→ 只用直接指针，极快 🚀
  ● 中文件 → 用到一级间接
  ● 大文件 → 用到二级/三级间接
  ● 动态扩展容易
  ● 缺点：大文件访问需多次磁盘读
    直接：1次  一级：2次  二级：3次  三级：4次
```

## 5. 空闲空间管理

> 跟踪记录文件卷中**未分配**的数据块。

### 5.1 位图（Bitmap）

```
用位图代表空闲数据块列表：

  111111111111111001110101011101111...
   Di = 0 → 数据块 i 空闲
   Di = 1 → 数据块 i 已分配

优点：简单 ✅
缺点：
  ● 大磁盘 → 大位图（160GB/4KB块 = 40M块 → 5MB位图）
  ● 找空闲块：需扫描位图找"0"
    → 假设均匀分布，需扫描约 n/r 位
    (n=总块数, r=空闲块数)
```

### 5.2 链表

```
空闲块用链表链接：

  空闲块1 → 空闲块2 → 空闲块3 → ...

不需要额外空间开销（空闲块本身存指针）
但遍历慢
```

### 5.3 链式索引（分组）

```
一组空闲块取第一个做"索引块"，存下一组空闲块的地址：

  ┌──────────┐    ┌──────────┐
  │索引块1    │───→│索引块2    │───→ ...
  │→空闲1    │    │→空闲n+1  │
  │→空闲2    │    │→空闲n+2  │
  │...       │    │...       │
  └──────────┘    └──────────┘

结合了位图的效率和链表的低空间开销
```

## 6. RAID（冗余磁盘阵列）

> 用多磁盘改善**吞吐量**（并行）和**可靠性**（冗余）。

### 6.1 RAID 级别总览

| RAID级别 | 技术 | 最少磁盘 | 容错数 | 写性能 | 空间效率 |
|:--:|------|:--:|:--:|------|:--:|
| **RAID-0** | 条带化，无冗余 | 2 | 0 ❌ | 高 | 100% |
| **RAID-1** | 镜像 | 2 | 1 | 中 | 50% |
| **RAID-4** | 条带化+专用校验盘 | 3 | 1 | 低(校验盘瓶颈) | (N-1)/N |
| **RAID-5** | 条带化+分布式校验 | 3 | 1 | 中 | (N-1)/N |
| **RAID-6** | 条带化+双冗余 | 4 | 2 | 低 | (N-2)/N |

### 6.2 各RAID工作原理

**RAID-0（磁盘条带化）**：

```
数据块分成子块，轮流存到不同磁盘上：
  块0→盘0, 块1→盘1, 块2→盘2, 块3→盘0, ...

并行读写 → 更大磁盘带宽
无冗余 → 一块盘坏，全卷丢失 ❌
空间效率：100%
```

**RAID-1（磁盘镜像）**：

```
同时向两个磁盘写入相同数据，可从任一磁盘读取

  主磁盘    镜像磁盘
  ┌────┐   ┌────┐
  │0110│   │0110│ ← 完全一样
  └────┘   └────┘

可靠性成倍增长 ✅   空间效率仅 50% ❌
```

**RAID-4（专用奇偶校验磁盘）**：

```
数据按块条带化，额外一块磁盘存奇偶校验信息

  盘1  盘2  盘3  校验盘
  ┌──┐ ┌──┐ ┌──┐ ┌──┐
  │11│ │10│ │00│ │01│ ← 校验数据
  └──┘ └──┘ └──┘ └──┘

允许任意一个数据盘故障后通过校验恢复 ✅
但校验盘是写瓶颈 ❌（每次写都要更新校验盘）
```

**RAID-5（分布式奇偶校验）**：

```
校验数据分散在所有磁盘上（不设专用校验盘）

  盘1    盘2    盘3    盘4    盘5
  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐
  │数据│ │数据│ │校验│ │数据│ │数据│ ← 校验分布在每块盘
  │校验│ │数据│ │数据│ │数据│ │数据│
  │数据│ │校验│ │数据│ │数据│ │数据│
  └──┘  └──┘  └──┘  └──┘  └──┘

消除 RAID-4 的写瓶颈 ✅  允许一个磁盘故障 ✅
```

**RAID-6（双冗余）**：

```
每组条带有两个冗余块 → 允许两个磁盘同时故障
最少需 4 块磁盘
空间效率：(N-2)/N
```

### 6.3 RAID 嵌套

```
RAID 0+1：先条带再镜像
  ┌─ RAID-0 ─┐
  │  条带化    │ ────→ 镜像到下方
  └──────────┘
  ┌─ RAID-0 ─┐
  │  条带化    │
  └──────────┘

RAID 1+0：先镜像再条带
  ┌─ RAID-1 ─┐  ┌─ RAID-1 ─┐
  │ 盘1→镜像  │  │ 盘3→镜像  │
  │ 盘2      │  │ 盘4      │
  └──────────┘  └──────────┘
       └─── RAID-0（条带化）───┘

兼顾性能和可靠性
```

## 7. FAQ

### Q1：硬链接和软链接的区别？

- **硬链接**：多个目录项指向同一个 inode。链接计数归零才删除。不能跨文件系统。
- **软链接**：存目标路径的快捷方式。原文件删除则失效。可跨文件系统。

### Q2：UFS 多级索引为什么用 13 个指针而不是更多？

10个直接指针覆盖 40KB（小文件够用）+ 1个一级间接(4MB) + 1个二级(4GB) + 1个三级(4TB)。13 个是经验值——大多数文件很小（≤40KB直接覆盖），少部分需要间接块。

### Q3：页缓存和数据块缓存有什么区别？

- **数据块缓存**：独立的磁盘缓存，按数据块管理
- **页缓存**：将文件数据映射为虚拟内存页，统一管理文件页和内存页（现代OS主流，如 Linux）

### Q4：RAID-5 比 RAID-4 好在哪里？

RAID-5 把校验数据**分散**到所有磁盘，消除了 RAID-4 专用校验盘的**写瓶颈**。

### Q5：文件描述符是什么？

打开文件的标识号（0=stdin, 1=stdout, 2=stderr）。OS 在打开文件表中维护其状态——文件指针、打开计数、磁盘位置、访问权限等。
