## 1. 虚拟存储的需求背景

### 1.1 程序规模增长远超内存增长

```
电脑游戏规模演进（PPT 例子）：
  一代 437K → 二代 883K → 三代 1.9M → 四代 6M
  → 五代 6.3M → 六代 59M → 七代 100M → 八代 138M

内存增长速度跟不上 → 需要一种技术，让小程序也能跑大程序
```

### 1.2 存储层次结构

```
理想存储器：容量大 + 速度快 + 便宜 + 非易失
现实存储器：没有一种设备能满足所有要求

┌──────────┬──────────┬─────────────┬──────────┬──────────┐
│  寄存器   │  缓存    │   内存      │  磁盘    │  磁带    │
├──────────┼──────────┼─────────────┼──────────┼──────────┤
│  1ns     │  2ns     │   10ns     │  10ms    │  100s    │
│  <1KB    │  1MB     │  64-512MB  │  5-50GB  │ 20-100GB │
└──────────┴──────────┴─────────────┴──────────┴──────────┘
 越快越小越贵 ←─────────────────────────→ 越慢越大越便宜

目标：组合这些层次，让用户感觉拥有"又快又大又便宜"的存储器
操作系统对存储的抽象：地址空间
```

### 1.3 解决方案演进

```
内存不够用时怎么办？

覆盖技术（Overlay）
  → 交换技术（Swapping）
    → 虚拟存储（Virtual Memory）

  程序员手动          OS自动换进程          OS自动换页面
  模块级粒度          进程级粒度            页面级粒度
```

## 2. 覆盖技术（Overlay）

### 2.1 目标与思路

> 在较小的可用内存中运行较大的程序。**由程序员手动完成**。

```
方法：
  ① 将程序划分为若干功能相对独立的模块
  ② 必要部分（常用功能）常驻内存
  ③ 可选部分（不常用功能）放在磁盘，用到时才装入
  ④ 不存在调用关系的模块 → 可相互覆盖，共用同一块内存区域
```

### 2.2 覆盖技术示例（PPT 例图）

```
程序 X 的调用结构：
            A (20K)
           /      \
        B(50K)   C(30K)
       /    \    /    \
    E(40K) F(30K)    D(20K)

关键观察：
  B 和 C 之间没有调用关系 → 不需要同时在内存
  E 和 F 之间没有调用关系 → 不需要同时在内存

内存分配（覆盖方案）：
┌──────────────┐
│  常驻区       │ A (20K)       ← 一直留在内存
├──────────────┤
│  覆盖区0(50K) │ B / E / F     ← 三者共用，只装当前需要的
├──────────────┤
│  覆盖区1(40K) │ C / D         ← 二者共用
└──────────────┘
总共：110K

全部加载需要：20 + 50 + 40 + 50 + 30 + 30 + 20 = 240K
覆盖后仅需：110K → 节省了 130K！
```

### 2.3 覆盖技术的不足

| 缺点 | 说明 |
|------|------|
| **增加编程难度** | 程序员必须划分模块，确定模块间的覆盖关系 |
| **增加执行时间** | 从外存装入覆盖模块（时间换空间） |
| **不透明** | 程序员手动管理，无法自动化 |

## 3. 交换技术（Swapping）

### 3.1 目标与实现

> 增加正在运行或需要运行的程序。**由操作系统自动完成**。

```
换出（swap out）：把一个进程的整个地址空间保存到外存
换入（swap in）：将外存中某进程的地址空间读入到内存
基本单位：整个进程的地址空间

          内存                         外存（磁盘）
    ┌─────────────┐              ┌───────────────┐
    │ P1（运行）   │              │  交换区        │
    │ P3（就绪）   │    换出       │  ┌─────────┐  │
    │             │─────────────→│  │ P2的整个  │  │
    │             │              │  │ 地址空间   │  │
    │             │    换入       │  │ 30MB     │  │
    │  P2回来了！  │←─────────────│  │         │  │
    └─────────────┘              │  └─────────┘  │
                                 └───────────────┘

触发时机：内存空间不够或有不够的可能时
搬运量：整个进程（可能几十MB）
```

### 3.2 交换技术面临的问题

| 问题 | 说明 |
|------|------|
| **交换区大小** | 需存放所有用户进程的内存映像拷贝 |
| **交换时机** | 何时交换？只在内存不足时 |
| **重定位** | 换出后再换入时，可能放到不同的物理位置 → 需要**动态地址映射**解决 |

### 3.3 覆盖 vs 交换

| | 覆盖技术 | 交换技术 |
|------|---------|---------|
| **粒度** | 程序内部模块 | **整个进程** |
| **作用范围** | 同一进程内部 | 内存中不同进程之间 |
| **由谁决定** | **程序员**手动划分 | **操作系统**自动完成 |
| **需要** | 模块间逻辑覆盖关系 | 不需要模块间的逻辑结构 |
| **透明度** | 不透明（程序员负担） | 透明（程序员无感知） |

## 4. 局部性原理（Principle of Locality）

> ⭐ **虚拟存储能工作的理论基础！如果没有局部性，虚拟存储只是理论玩具。**

### 4.1 定义

> 程序在执行过程中的一个**较短时期**，所执行的指令地址和指令的操作数地址，**分别局限于一定区域**。

### 4.2 三种局部性

| 类型 | 含义 | 典型例子 |
|------|------|---------|
| **时间局部性** | 一条指令/数据被访问后，**短期内很可能再次被访问** | 循环中同一变量被反复读写；频繁调用的函数 |
| **空间局部性** | 当前指令/数据被访问后，**邻近的指令/数据也很可能被访问** | 顺序执行的代码；数组按行遍历 |
| **分支局部性** | 跳转指令两次执行，**很可能跳到相同的位置** | 循环体跳转始终回到循环头 |

### 4.3 局部性的意义

```
因为局部性，程序在任何时刻只需要 一小部分 页面在内存：

  进程 100MB，但某一时刻活跃页面可能只有 10MB
  → 只需 10MB 物理内存就能让 100MB 程序跑起来
  → 缺页率极低，性能损失可接受
```

### 4.4 经典例子：数组访问方式对缺页率的影响（PPT）

```c
int A[1024][1024];  // 按行存放，每行在一个页面中
// 页面大小：4KB
// 分配给进程的物理页面数：1  ← 只有1个物理帧！

// 方法1：按列访问（破坏空间局部性）
for (j = 0; j < 1024; j++)
  for (i = 0; i < 1024; i++)
    A[i][j] = 0;

// 方法2：按行访问（利用空间局部性）
for (i = 0; i < 1024; i++)
  for (j = 0; j < 1024; j++)
    A[i][j] = 0;
```

```
方法1（按列）的访问序列：
  A[0][0], A[1][0], A[2][0]... → 每次跳一页 → 1024×1024 次缺页！

方法2（按行）的访问序列：
  A[0][0], A[0][1], A[0][2]... → 连续在同一页 → 仅 1024 次缺页

结果：方法1 的缺页次数是方法2 的 1024 倍！
     同样只有一个物理帧，利用局部性 → 性能天差地别。
```

## 5. 虚拟存储概念

### 5.1 基本思想

```
物理内存 + 磁盘 = 虚拟存储

┌─────────────────────────────────────────┐
│              虚拟地址空间                  │
│         （进程以为它拥有的全部）              │
│                                           │
│   ┌──────────────────────────┐          │
│   │    正在用的 → 在物理内存    │          │
│   ├──────────────────────────┤          │
│   │    暂时不用的 → 在磁盘      │          │
│   ├──────────────────────────┤          │
│   │    还没分配的 → 不存在      │          │
│   └──────────────────────────┘          │
└─────────────────────────────────────────┘

操作系统自动在内存和磁盘之间搬运页面
进程完全感知不到！
```

### 5.2 原理

```
① 装载程序时：只装入当前指令执行需要的部分页面或段，就启动程序
② 运行时：
   ● 需要的指令/数据不在内存 → 缺页（或缺段）
   ● 处理器通知 OS → OS 从外存调入
   ● OS 将暂时不用的页面/段保存到外存
③ 重新执行刚才失败的指令 → 这次命中了
```

### 5.3 虚拟存储的基本特征

| 特征 | 含义 |
|------|------|
| **大用户空间** | 提供给用户的虚拟内存可**大于**实际的物理内存 |
| **部分交换** | 只对**部分**虚拟地址空间进行调入调出（不是整个进程！） |
| **不连续性** | 物理内存分配非连续，虚拟地址空间使用非连续 |

### 5.4 支持技术

```
硬件：页式或段式存储中的地址转换机制（MMU / TLB）
      需要能检测"页面不在内存"并触发异常

操作系统：
  管理内存和外存间页面的换入换出
  页面置换算法（选哪个页面换出）
  缺页异常处理
```

### 5.5 实现方式

- **虚拟页式存储**（Virtual Paging）← Lec8 重点
- **虚拟段式存储**（Virtual Segmentation）

## 6. 虚拟页式存储

### 6.1 思路

> 在页式存储管理的基础上，增加**请求调页**和**页面置换**。

```
传统分页：所有页必须全在内存             虚拟页式存储：部分页在内存即可

┌──┐┌──┐┌──┐┌──┐┌──┐                   ┌──┐┌──┐
│页0││页1││页2││页3││页4│ ← 全在内存      │页0││页3│ ← 只在内存
└──┘└──┘└──┘└──┘└──┘                   └──┘└──┘
                                              │
                                       页1,2,4 在磁盘上，用到时调入
```

### 6.2 虚拟页式存储的页表项

> 比纯分页多了更多标志位，用于支持缺页处理和页面置换。

```
页表项结构：
┌──────────────┬────┬────┬────┬────┬─────────┐
│  物理页帧号    │驻留位│修改位│访问位│保护位│  ...    │
│   (20位)     │ P  │ D  │ A  │    │         │
└──────────────┴────┴────┴────┴────┴─────────┘
          ↑               ↑
    纯分页就有（Lec6）     虚拟存储新增的关键标志

四个关键标志位：

┌────────┬────────────────────────────────────────┐
│ P (驻留位) │ 1=该页在内存，页表项有效                     │
│         │ 0=该页在外存，访问将导致 缺页异常 ← 虚拟存储核心 │
├────────┼────────────────────────────────────────┤
│ D (修改位) │ 1=内存中的该页被修改过 → 换出时需写回磁盘        │
│         │ 0=未被修改 → 换出时直接丢弃                │
├────────┼────────────────────────────────────────┤
│ A (访问位) │ 表示该页是否被访问过（读或写）→ 用于页面置换算法   │
├────────┼────────────────────────────────────────┤
│ 保护位    │ 只读 / 可读写 / 可执行 等访问权限              │
└────────┴────────────────────────────────────────┘
```

### 6.3 虚拟页式存储示例（PPT 例子）

```
设定：
  16位逻辑地址（0~64K）
  物理内存 32K
  页面大小 4K = 16页逻辑空间，8帧物理空间

逻辑地址空间（16页）           物理地址空间（8帧）
60K-64K  [页15]              28K-32K  [帧7]
56K-60K  [页14]              24K-28K  [帧6]
...                           ...
 8K-12K  [页2] ← 驻留=1 →     8K-12K  [帧2]
 4K-8K   [页1] ← 驻留=1 →     4K-8K   [帧1]
 0K-4K   [页0] ← 驻留=1 →     0K-4K   [帧0]

MOV REG, 8192
  → 8192 在页2（8K~12K），页表[2]驻留位=1 ✅ → 直接访问

MOV REG, 32780
  → 32780 在页8（32K~36K），页表[8]驻留位=0 ❌ → 缺页异常！
  → OS 从外存调入页8 → 更新页表 → 重新执行指令 ✅
```

## 7. 缺页异常（Page Fault）

### 7.1 完整处理流程

```
产生缺页异常的指令 i
        │
        ▼
┌──────────────────────────────────────┐
│ ① 查找缺页 p 在外存中的位置             │
│                                      │
│ ② 在内存中找一个物理帧 f：              │
│    ├─ 有空闲帧 → 直接分配帧 f           │
│    └─ 无空闲帧 → 页面置换               │
│        A. 选一个要换出的帧 f，对应逻辑页 q │
│        B. 如果 q 被修改过(D=1) → 写回外存│
│        C. 修改 q 的页表项驻留位 = 0       │
│                                      │
│ ③ 将需要的页 p 从外存装入到帧 f           │
│                                      │
│ ④ 修改页 p 的页表项：                  │
│    驻留位 = 1, 物理帧号 = f              │
│                                      │
│ ⑤ 重新执行导致异常的指令 i → 这次命中！    │
└──────────────────────────────────────┘
```

### 7.2 外存管理

```
未被映射的页保存在哪里？

┌──────────────┬────────────────────────┐
│ 代码段        │ 可执行二进制文件本身       │
│ 动态共享库     │ 动态调用的库文件          │
│ 其他段（堆/栈） │ 交换空间（特殊磁盘分区/文件）│
└──────────────┴────────────────────────┘

要求：能快速找到在外存中的页面位置
交换空间：采用特殊格式存储未被映射的页面，比文件系统更快
```

### 7.3 X86 页表结构（PPT 实例）

```
32位 x86 虚拟地址，二级页表：

┌──────────┬──────────┬──────────────┐
│ 一级(10位) │ 二级(10位) │  偏移(12位)   │
└──────────┴──────────┴──────────────┘

CR3 → 一级页表(页目录)1024项
         ↓
      二级页表 1024项
         ↓
      物理帧(4KB)

X86 页表项：
┌─────────────────┬───┬──┬──┬──┬──┬──┬──┬──┐
│ 物理帧号(20位)    │AVL│ D│ A│CD│WT│U/│W │P │
└─────────────────┴───┴──┴──┴──┴──┴──┴──┴──┘
                  保留 修改 访问 缓存 写策 用户 可写 驻留
                              略  态  留

P  - 驻留位：1=在内存  0=在外存（缺页）
W  - 可写标志
U/S- 用户态/内核态
WT - Write-through(1) / Write-back(0)
CD - Cache Disabled
A  - 访问位（CPU 硬件自动置1，OS 可清零）
D  - 修改位（一级页表此项为0，二级才有）
AVL- 保留位，OS 可用
```

## 8. 虚拟页式存储的性能分析

### 8.1 有效存储访问时间（EAT）

```
EAT = 访存时间 × (1-p)
    + 缺页异常处理时间 × 缺页率 p

考虑页面修改（q = 页修改概率）：
EAT = 10(1-p) + 5,000,000p(1+q)

数值（PPT 例子）：
  访存时间 = 10ns
  磁盘访问时间 = 5ms = 5,000,000ns  ← 差了 50 万倍！
  缺页率 p
  页修改概率 q
```

### 8.2 缺页率对性能的影响

```
缺页率 p = 0.001（千分之一），q=0.5：
  EAT = 10×0.999 + 5,000,000×0.001×1.5
      = 9.99 + 7500
      = 7510 ns  ← 比纯内存（10ns）慢了 750 倍！

缺页率 p = 0.00001（十万分之一）：
  EAT = 10×0.99999 + 5,000,000×0.00001×1.5
      ≈ 10 + 75
      = 85 ns  ← 勉强可以接受

结论：缺页率必须 极低（10⁻⁵ ~ 10⁻⁶ 级别）才能保证性能
      局部性原理 是保证低缺页率的关键！
```

## 9. FAQ

### Q1：覆盖、交换、虚拟存储的区别是什么？

| | 覆盖 | 交换 | 虚拟存储 |
|------|------|------|---------|
| 粒度 | 程序内部模块 | **整个进程** | **页面**（4KB） |
| 谁管理 | 程序员手动 | OS 自动 | OS + MMU 硬件 |
| 搬运量 | 部分模块 | 整个进程（几十MB） | 单个页面（4KB） |
| 透明度 | ❌ 程序员负担 | ✅ 透明 | ✅ 完全透明 |

交换技术换整个进程；虚拟存储只换部分页面。虚拟存储 = 交换技术的细粒度进化版。

### Q2：局部性原理为什么是虚拟存储的基石？

因为缺页处理的代价极大（磁盘比内存慢 50 万倍），缺页率必须极低。局部性原理保证了程序在短时间内只访问一小部分页面，缺页率可以降到 \(10^{-6}\) 级别，性能才能接受。没有局部性，虚拟存储只是理论玩具。

### Q3：驻留位、修改位、访问位分别干什么？

- **驻留位(P)**：0 → 缺页异常，OS 去磁盘调入
- **修改位(D)**：换出时判断是否需要写回磁盘（1=需要写回，0=直接丢弃）
- **访问位(A)**：给页面置换算法用（最近没访问过的优先换出）

### Q4：物理内存有空闲帧和没有空闲帧，缺页处理有什么不同？

- **有空闲帧**：直接分配 → 装入页面 → 更新页表
- **无空闲帧**：先**页面置换**（选一个换出的 → 脏页写回 → 驻留位清零）→ 再装入新页面

### Q5：按列访问数组为什么比按行访问缺页多？

数组按行存放，每行在一个页面中。按行访问 → 连续访问同一页 → 空间局部性好 → 缺页少。按列访问 → 每访问一个元素跳一页 → 破坏空间局部性 → 缺页暴增。
