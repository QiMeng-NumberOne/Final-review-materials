## 1. 进程的概念

### 1.1 进程的定义

> 进程是指一个具有一定独立功能的**程序在一个数据集合上的一次动态执行过程**。

```
进程 = 程序 + 执行状态

源代码 → 编译 → 链接 → 可执行文件(.exe/ELF)
                            ↓
                       加载到内存执行
                            ↓
                         进程（动态）

同一个程序执行两次 → 两个不同的进程（如开两个终端窗口）
```

### 1.2 进程的组成

```
进程包含了正在运行的一个程序的所有状态信息：
┌──────────────────────────────────────┐
│ 代码 (code)    │ 程序的指令             │
│ 数据 (data)    │ 全局变量、静态变量       │
│ 堆 (heap)      │ malloc 分配，向下增长   │
│ 栈 (stack)     │ 局部变量、函数调用帧     │
│ CPU 寄存器状态  │ IP、SP、通用寄存器...   │
│ 系统资源       │ 打开的文件、网络连接...   │
│ PCB            │ 进程的管理信息          │
└──────────────────────────────────────┘
```

### 1.3 进程与程序的区别

| | 程序 (Program) | 进程 (Process) |
|------|---------|---------|
| **本质** | 静态的指令集合（磁盘上的文件） | 动态的执行过程 |
| **存在时间** | **永久**存在 | **暂时**存在（运行时） |
| **组成** | 代码 + 数据（ELF/PE 文件） | 程序 + 数据 + PCB + 执行状态 |

### 1.4 进程的四大特点

```
动态性：可动态创建、结束进程
并发性：多个进程可被独立调度并占用 CPU
独立性：不同进程有独立地址空间，互不干扰
制约性：访问共享资源或进程间同步时产生制约
```

## 2. 进程控制块（PCB）

### 2.1 定义

> **PCB（Process Control Block）**是 OS 管理控制进程所用的信息集合。**PCB 是进程存在的唯一标志。**

```
每个进程在 OS 中都有一个对应的 PCB：
  进程创建 → 生成 PCB
  进程终止 → 回收 PCB
  进程调度 → 更新 PCB 中的状态和 CPU 使用信息
  进程切换 → 将 CPU 现场保存到 PCB → 从新进程的 PCB 恢复
```

### 2.2 PCB 包含的信息

```
┌─────────────────────────────────────────────────┐
│              PCB 三大类信息                        │
├─────────────────────────────────────────────────┤
│                                                 │
│ ① 进程标识信息                                    │
│    PID（进程ID）、UID（用户ID）、进程组ID...         │
│                                                 │
│ ② 处理机现场保存（CPU 上下文）                      │
│    通用寄存器：AX、BX、CX...                        │
│    指令指针 IP、栈指针 SP                           │
│    CR3（页表基址！← 联系 Lec6 PTBR）                │
│    标志寄存器                                     │
│                                                 │
│ ③ 进程控制信息                                    │
│    调度和状态：进程状态、优先级、CPU 使用时间...        │
│    存储管理：指向进程内存映像的数据结构（页表位置...）   │
│    I/O 状态：打开的文件列表、分配的设备...            │
│    进程间通信：信号、管道、消息队列...                │
│    连接信息：指向同一状态队列中下一个 PCB 的指针       │
└─────────────────────────────────────────────────┘
```

### 2.3 PCB 的组织方式

**链表方式**：PCB 内部嵌 `next` 指针，同一状态的 PCB 串成链表。

```
struct PCB {
    int pid;           // 进程ID
    int state;         // 就绪/等待/运行...
    int priority;      // 调度优先级
    void *cr3;         // 页表基址（CR3的值）
    int *files;        // 打开文件列表指针
    // ... 其他字段
    
    struct PCB *next;  // ← 链表指针，串成队列
};
```

```
就绪队列（head_ready 指向链表头）：
  ┌────────┐    ┌────────┐    ┌────────┐
  │ PCB_A  │───→│ PCB_B  │───→│ PCB_C  │───→ NULL
  │ 就绪    │    │ 就绪    │    │ 就绪    │
  │next=●──│    │next=●──│    │next=NULL│
  └────────┘    └────────┘    └────────┘
    ↑
  head_ready

磁盘等待队列（head_disk 指向链表头）：
  ┌────────┐    ┌────────┐
  │ PCB_D  │───→│ PCB_E  │───→ NULL
  │ 等待磁盘 │    │ 等待磁盘 │
  └────────┘    └────────┘
    ↑
  head_disk

状态变化 = PCB 从一个链表摘下，挂到另一个链表！
```

**索引表方式**：用数组存放链表头指针，按状态类型索引。

```
索引表（固定数组）：
┌─────────┐
│ [0] 就绪 │───→ PCB_1 → PCB_2 → NULL
├─────────┤
│ [1] 磁盘 │───→ PCB_3 → NULL
├─────────┤
│ [2] 键盘 │───→ PCB_4 → NULL
├─────────┤
│ [3] 网络 │───→ NULL
├─────────┤
│  ...    │
└─────────┘

区别：链表 = 几个全局头指针；索引表 = 一个数组，state→下标
```

## 3. 进程状态模型

### 3.1 三状态模型

```
                   创建(New)
                      │
                      ▼
         ┌──────────────────────────┐
         │        就绪(Ready)        │ ← 等待 CPU
         └──────┬──────────┬────────┘
                │ 被调度   │
                ▼          │ 时间片完
         ┌──────────┐     │
         │ 运行      │─────┘
         │ (Running)│
         └────┬─────┘
              │ 等待事件（如等 I/O）
              ▼
         ┌──────────────┐
         │ 等待(Blocked) │ ← 等待某事件发生
         └───┬──────────┘
             │ 事件发生
             └──────→ 回到 就绪
              │
              ▼
          结束(Exit)
```

| 状态 | 含义 |
|------|------|
| **创建(New)** | 正在被创建，尚未就绪 |
| **就绪(Ready)** | 已获得除 CPU 外的资源，等待被调度 |
| **运行(Running)** | 正在 CPU 上执行 |
| **等待(Blocked)** | 等待某事件（如 I/O 完成）而暂停，也称阻塞 |
| **结束(Exit)** | 进程正在消失 |

### 3.2 状态转换触发条件

| 转换 | 触发条件 |
|------|---------|
| 创建 → 就绪 | 进程初始化完成 |
| 就绪 → 运行 | 被调度程序选中 |
| 运行 → 就绪 | 时间片用完，被抢占 |
| 运行 → 等待 | 请求资源且必须等待（如 `read()` 系统调用） |
| 等待 → 就绪 | 等待的事件到达（如磁盘 I/O 完成），被唤醒 |
| 运行 → 结束 | 正常退出、错误退出、被杀死 |

### 3.3 挂起进程模型（七状态）

> **挂起(Suspend)**：把一个进程从**内存**转到**外存（磁盘）**。
> **激活(Activate)**：把一个进程从**外存**转回**内存**。

```
              ┌───────── 内存 ─────────┐    ┌──── 外存(磁盘) ────┐
              │                       │    │                     │
创建 ──────→ 就绪(Ready) ←────── 激活 ───── 就绪挂起(Ready-suspend)
              │  ↑  │                │    │  ↑       ↑          │
              │  │  │ 时间片完        │    │  │       │          │
              │  │  ▼                │    │  │       │          │
              │  │ 运行(Running) ────│─挂─│──┘       │          │
              │  │  │                │    │          │          │
              │  │  │ 等待事件         │    │          │          │
              │  │  ▼                │    │          │          │
              │  │ 等待(Blocked) ←───│─激─│── 等待挂起(Blocked-suspend)
              │  │  │                │    │    ↑                  │
              │  │  ▼                │    │    │                  │
              │  │ 结束               │    │    │   事件发生       │
              │                       │    │    └────── 从等待挂起 │
              └───────────────────────┘    │          变为就绪挂起  │
                                           └─────────────────────┘
```

**两个挂起状态**：

| 状态 | 含义 |
|------|------|
| **等待挂起** (Blocked-suspend) | 进程在外存，**且**在等待某事件 |
| **就绪挂起** (Ready-suspend) | 进程在外存，但事件已发生，进内存即可运行 |

### 3.4 挂起与激活的触发条件

**挂起（内存 → 外存）的原因只有两个：**

```
① 内存不够了
   → 需要进程腾出空间
   → 把一些进程赶到磁盘

② 优先级决策
   → 高优先级进程需要进内存
   → 低优先级先出去等着
```

| 转换 | 触发条件 |
|------|---------|
| **等待 → 等待挂起** | 所有进程都在等 I/O（没就绪进程），内存被等待进程白白占着；或就绪进程需要大块内存 |
| **就绪 → 就绪挂起** | 高优先级进程在磁盘上变就绪了需要进内存，低优先级就绪进程让路 |
| **运行 → 就绪挂起** | 抢先式系统中，高优先级等待挂起进程因事件就绪 → 当前运行进程被抢占并挂起 |

**激活（外存 → 内存）：**

| 转换 | 触发条件 |
|------|---------|
| **就绪挂起 → 就绪** | 没有内存中的就绪进程（都在磁盘）；或挂起进程优先级高于内存中的就绪进程 |
| **等待挂起 → 等待** | 内存释放了足够空间，且有高优先级等待挂起进程 |

### 3.5 进程切换（Context Switch）

```
进程A运行中 → 时间片到 / 系统调用阻塞
         → ① 保存 A 的 CPU 现场到 PCB_A（IP、SP、寄存器...）
         → ② schedule() 选下一个进程 B
         → ③ 从 PCB_B 恢复 CPU 现场（包括加载 CR3 页表基址！）
         → ④ CPU 开始执行进程B

进程调度中的队列流转：
  接收进程 → 就绪队列 → 被调度 → CPU运行
                                │
              时间片用完 ←───────┘
              等待事件 → 等待队列 → 事件发生 → 回到就绪队列
              结束 → 终止
```

## 4. 为什么引入线程

### 4.1 单进程方案的问题

```c
// 一个 MP3 播放器的三个功能
main() {
    while(TRUE) {
        Read();         // ① 从MP3文件读取数据
        Decompress();   // ② 解压缩
        Play();         // ③ 播放音频
    }
}
```

```
问题：
  ① 三个函数不能并发 → CPU 和 I/O 不能同时工作 → 利用率低
  ② 播放声音可能不连贯（解压时播放暂停）
```

### 4.2 多进程方案的问题

```c
// 进程1               进程2               进程3
main() {              main() {            main() {
  while(1) Read();      while(1) Decomp();  while(1) Play();
}                     }                   }
```

```
问题：
  ① 进程间通信困难（各自独立地址空间，数据怎么传？）
  ② 开销大：创建进程、切换进程（要切页表！）都很昂贵
```

### 4.3 线程的解决思路

> 在进程内部增加一类实体，满足两个特性：
> 1. 实体之间**可以并发执行**
> 2. 实体之间**共享相同的地址空间**

## 5. 线程的概念

### 5.1 定义

> 线程是进程的一部分，是**进程中的指令流执行的最小单元**，是 **CPU 调度的基本单位**。

```
进程的两个角色被拆开：

  进程 = 资源分配单位（拥有地址空间、代码、数据、文件...）
  线程 = CPU 调度单位   （拥有寄存器、栈、指令指针...）
```

### 5.2 线程与进程的关系

```
单线程进程：                      多线程进程：
┌──────────────────┐            ┌──────────────────────┐
│ 代码   数据   文件  │            │ 代码   数据   文件      │ ← 共享
├──────────────────┤            ├──────────────────────┤
│    线程           │            │ 线程1 │ 线程2 │ 线程3  │
│  ┌────┐          │            │┌────┐ ┌────┐ ┌────┐  │
│  │寄存器│         │            ││寄存器││寄存器││寄存器│  │ ← 各自独立
│  │SP PC│         │            ││SP PC││SP PC││SP PC│  │
│  │栈   │          │            ││栈   ││栈   ││栈   │  │
│  └────┘          │            │└────┘ └────┘ └────┘  │
└──────────────────┘            └──────────────────────┘

线程 = 进程 - 共享资源
每个线程独享：寄存器、栈、指令指针（IP/SP/PC）
所有线程共享：代码、数据、堆、打开的文件
```

### 5.3 线程的优点与缺点

| 优点 | 缺点 |
|------|------|
| ✅ 一个进程可有多个线程并发 | ❌ **一个线程崩溃 → 整个进程崩溃** |
| ✅ 各线程共享地址空间（传指针即可通信） | ❌ 共享带来同步问题（需锁机制） |
| ✅ 线程创建/切换快（不切页表） | |
| ✅ 多线程可充分利用多核 CPU | |

### 5.4 线程与进程对比

| | 进程 | 线程 |
|------|------|------|
| **角色** | 资源分配单位 | CPU 调度单位 |
| **地址空间** | 独立 | **共享**进程空间 |
| **独享资源** | 全部资源 | 寄存器 + 栈 |
| **创建/终止速度** | 慢 | **快** |
| **切换开销** | 大（需切换页表 CR3） | **小**（不改 CR3） |
| **通信** | 需 IPC（管道、消息队列） | 直接共享内存 |
| **崩溃影响** | 不影响其他进程 | 可能导致整个进程崩溃 |

## 6. 线程的实现方式

### 6.1 三种实现方式

| 实现方式 | TCB 在哪 | 谁管理和调度 | 代表 |
|------|------|------|------|
| **用户线程** | 用户空间 | 线程库（用户态） | POSIX Pthreads |
| **内核线程** | 内核空间 | OS 内核 | Windows、Linux |
| **轻量级进程(LWP)** | 内核空间 | 内核 + 线程库协作 | Solaris |

### 6.2 用户线程

```
┌──────── 用户空间 ────────────┐
│  ┌─────────┐ ┌─────────┐   │
│  │用户线程1 │ │用户线程2 │   │ ← 线程库创建和管理
│  │ TCB(用户)│ │ TCB(用户)│   │    线程库调度（用户态切换）
│  │ 栈       │ │ 栈       │   │
│  └──────────┘ └──────────┘   │
│         ↓                    │
│  ┌────────────┐              │
│  │  线程库     │              │ ← 调度、同步全在用户态
│  └─────┬──────┘              │    不经过内核！
├────────┼─────────────────────┤
│        ▼                     │
│  ┌──────────┐               │
│  │  内核     │               │ ← 内核只看到一个进程
│  │  PCB     │               │    不知道里面有多个线程
│  └──────────┘               │
└──────── 内核空间 ────────────┘
```

**特征**：

| 优点 | 缺点 |
|------|------|
| ✅ 切换快（不陷内核） | ❌ 一线程做阻塞系统调用 → **整个进程阻塞** |
| ✅ 可用于不支持线程的 OS | ❌ 不支持线程级抢占 |
| ✅ 每个进程可自定义调度算法 | ❌ 按进程分配 CPU，多线程时每线程时间片少 |

### 6.3 内核线程

```
┌──────── 用户空间 ────────────┐
│  ┌─────────┐ ┌─────────┐   │
│  │内核线程1 │ │内核线程2 │   │ ← 线程的栈在用户空间
│  │ 栈       │ │ 栈       │   │
│  └──────────┘ └──────────┘   │
├────────┼───────────┼─────────┤
│        ▼           ▼         │
│  ┌───────┐   ┌───────┐      │
│  │ TCB1  │   │ TCB2  │      │ ← TCB 在内核空间！
│  └───┬───┘   └───┬───┘      │    内核维护和调度
│      └─────┬──────┘          │
│            ▼                 │
│  ┌────────────────┐         │
│  │  内核调度器      │         │ ← 以线程为单位分配 CPU
│  │  独立调度每个线程  │         │
│  └────────────────┘         │
│      PCB (进程)              │
└──────── 内核空间 ────────────┘
```

**特征**：

| 优点 | 缺点 |
|------|------|
| ✅ 一线程阻塞不影响其他线程 | ❌ 创建/切换开销大（需进内核态） |
| ✅ 以线程为单位分配 CPU 时间 | ❌ 需系统调用创建和管理 |
| ✅ 多线程进程可获得更多 CPU 时间 | |

### 6.4 用户线程与内核线程的对应关系

```
① 多对一 (M:1):
  ┌──┬──┬──┐
  │UT│UT│UT│ ← 多个用户线程
  └──┴──┴──┘
      ↓
    ┌──┐
    │KT│ ← 一个内核线程
    └──┘
  缺点：一线程阻塞 → 全进程阻塞

② 一对一 (1:1):
  ┌──┐┌──┐┌──┐
  │UT││UT││UT│
  └──┘└──┘└──┘
   │   │   │
  ┌──┐┌──┐┌──┐
  │KT││KT││KT│
  └──┘└──┘└──┘
  优点：互不影响
  缺点：内核线程数多 → 开销大

③ 多对多 (M:N):
  ┌──┬──┬──┬──┐
  │UT│UT│UT│UT│
  └──┴──┴──┴──┘
    ↘  ↙   ↘  ↙
   ┌──┬──┬──┐
   │KT│KT│KT│ ← 内核线程池
   └──┴──┴──┘
  优点：折衷——兼顾并发性和开销
```

### 6.5 轻量级进程（LWP）

```
内核支持的用户线程。每个 LWP 由单独的内核线程支撑。

└──┬─┴──┬┘        └──────────────┘
```

## 7. 用户线程 vs 内核线程 vs 轻量级进程

| | 用户线程 | 内核线程 | LWP |
|------|:---:|:---:|:---:|
| TCB 在哪 | 用户空间 | 内核空间 | 内核空间 |
| 谁管理 | 线程库（用户态） | OS 内核 | 内核 + 线程库 |
| 创建/切换开销 | **小** | 大 | 中 |
| 一线程阻塞 | 全进程阻塞 ❌ | 不影响其他 ✅ | 不影响 ✅ |
| CPU 分配单位 | 整个进程 | 每个线程 | 每个 LWP |
| 线程切换 | 用户态，极快 | 内核态，较慢 | 内核态 |
| 内核感知线程 | ❌ 不知道 | ✅ 知道 | ✅ 知道 |

## 8. 内核空间与用户空间

### 8.1 内核是什么？

> **内核是一段始终驻留在物理内存中的程序**，拥有 CPU 最高权限（内核态），开机最先加载，关机才退出。

```
内核的职责：
  ├── 内存管理（你学的分段/分页/虚拟存储/页面置换）
  ├── 进程管理（PCB/状态转换/调度/挂起）
  ├── 文件系统
  ├── 设备驱动（键盘/磁盘/显示器/网卡...）
  └── 响应用户程序的请求（系统调用）
```

进入内核态只有三种途径：**系统调用**、**中断**、**异常**。

### 8.2 内核空间 vs 用户空间

> 不是两个物理地方，而是**逻辑地址空间被划了一道分界线**。

```
32位系统，4GB 逻辑地址空间：

0xFFFFFFFF ┌────────────────────┐
           │    内核空间 (1GB)    │ ← U/S=0，只有内核态能访问
           │  内核代码            │    所有进程共享这个区域
           │  所有PCB             │    映射到同一块物理内存
           │  内核线程TCB         │
           │  页表               │
           │  文件缓存            │
0xC0000000 ├────────────────────┤ ← 分界线
           │    用户空间 (3GB)    │ ← U/S=1，用户态就能访问
           │  你的代码 .text       │    每个进程有独立的一份
           │  全局变量 .data       │    映射到不同的物理帧
           │  堆 heap             │
           │  线程栈 stack         │
           │  用户线程TCB          │
           │  共享库 libc.so      │
0x00000000 └────────────────────┘

分界线靠页表项的 U/S 位实现（回顾 Lec6）：
  U/S = 0 → 只有内核态能访问
  U/S = 1 → 用户态也能访问
```

### 8.3 为什么 PCB 放在内核空间？

```
安全原因：
  如果 PCB 在用户空间 → 你的程序写了个野指针
  → 可能覆盖自己 PCB 里的"页表基址 CR3"
  → 整个进程内存映射全乱 → 可能看到别的进程的数据
  → 安全灾难

所以 PCB 必须在用户摸不到的地方 → 内核空间
你的代码/数据/堆/栈在用户空间 → 随便用
```

### 8.4 各内容存放位置汇总

```
┌────────────────┬─────────────────┬──────────────────┐
│     内容        │ 在逻辑地址空间    │   在物理内存中     │
├────────────────┼─────────────────┼──────────────────┤
│ 你的代码(.text) │  用户空间        │   某个物理帧      │
│ 全局变量(.data) │  用户空间        │   某个物理帧      │
│ 堆(malloc)     │  用户空间        │   多个物理帧      │
│ 线程栈          │  用户空间        │   多个物理帧      │
│ 共享库(libc)   │  用户空间        │   共享的物理帧     │
├────────────────┼─────────────────┼──────────────────┤
│ PCB           │  内核空间        │   物理内存内核区    │
│ 内核线程TCB    │  内核空间        │   物理内存内核区    │
│ 用户线程TCB    │  用户空间        │   物理内存用户区    │
│ 页表          │  内核空间        │   物理内存内核区    │
│ 内核代码       │  内核空间        │   物理内存内核区    │
└────────────────┴─────────────────┴──────────────────┘

全部最终都在物理内存条上！
只是逻辑地址空间里分了"谁能访问谁不能访问"。
```

## 9. 进程地址空间与多线程

### 9.1 单线程进程的地址空间

```
0 ┌──────────────┐
  │ 代码段 .text  │ ← 只读
  ├──────────────┤
  │ 数据段 .data  │ ← 全局变量
  ├──────────────┤
  │ 堆 heap       │ ← malloc
  │      ↓       │
  │      ↑       │
  │ 栈 stack      │ ← 局部变量
  ├──────────────┤
  │ 共享库        │
  └──────────────┘ MAXprog
```

### 9.2 多线程进程的地址空间

```
0 ┌──────────────┐
  │ 代码段 .text  │ ← 所有线程共享（只读）
  ├──────────────┤
  │ 数据段 .data  │ ← 所有线程共享
  ├──────────────┤
  │ 堆 heap       │ ← 所有线程共享（malloc出来的大家都能用）
  │      ↓       │
  │              │
  │  线程1 栈     │ ← 线程1 独享
  ├──────────────┤
  │  线程2 栈     │ ← 线程2 独享
  ├──────────────┤
  │  线程3 栈     │ ← 线程3 独享
  ├──────────────┤
  │ 共享库        │ ← 所有线程共享
  └──────────────┘ MAXprog

关键：所有线程在同一个逻辑地址空间！
     线程间传指针就能共享数据
     不需要管道/消息队列等进程间通信
```

### 9.3 与前面章节（分段/分页/虚拟存储）的联系

```
一个进程从创建到运行的完整链路，串起你学的所有知识：

① 创建进程 → 创建 PCB（Lec11）
② 建立段表 + 页表（Lec6 段页式）
   → 大部分页表项驻留位 = 0
   → PCB 中记录页表基址（CR3 的值）
③ 进程被调度 → 从 PCB 读页表基址 → 写 CR3（Lec6 PTBR）
④ CPU 执行第一条指令 → 缺页！驻留位 = 0（Lec8）
⑤ OS 分配物理帧 → 装入代码 → 更新页表 → 重新执行（Lec8）
⑥ 线程切换 → CR3 不变！只切 SP 和寄存器（Lec11）
   → 这就是线程切换比进程切换快的原因（不用切页表！）
⑦ 进程切换 → 保存当前 CR3 到 PCB → 加载新进程的 CR3
⑧ 内存满了 → 页面置换算法选一页换出（Lec9）
⑨ 更严重的 → 整个进程挂起到磁盘（Lec11 挂起模型）
```

## 10. FAQ

### Q1：PCB 和 TCB 放在哪里？

- **PCB** → 内核空间（内核管理，用户不能碰）
- **内核线程 TCB** → 内核空间（内核维护）
- **用户线程 TCB** → 用户空间（线程库维护，用户态直接访问）

都在物理内存里，区别在逻辑地址空间的哪个区域。

### Q2：什么是响应时间？

从用户**发出请求**到系统**第一次响应**的时间。不是"创建→就绪"，而是包含创建/唤醒/排队等待/执行/输出的完整链路。

### Q3：挂起状态转换的触发条件是什么？

挂起只有两大原因：**内存不够**或**优先级决策**。

| 转换 | 触发条件 |
|------|---------|
| 等待 → 等待挂起 | 没就绪进程或内存不够，把等待进程赶出内存 |
| 就绪 → 就绪挂起 | 高优先级进程要进内存，低优先级就绪让路 |
| 运行 → 就绪挂起 | 高优先级等待进程事件发生，抢占并挂起当前进程 |

### Q4：内核空间和用户空间有什么区别？

- **用户空间**：用户态就能访问（U/S=1），每个进程独立一份
- **内核空间**：必须内核态才能访问（U/S=0），所有进程共享同一块物理内存映射

内核空间也是逻辑地址空间的一部分，不是物理内存本身，但映射到物理内存的内核区域。

### Q5：用户线程和内核线程的本质区别？

不是"跑在哪里"的不同——都在进程地址空间里执行。区别在**谁管理**：

- 用户线程：TCB 在用户空间，线程库调度，内核看不到 → 切换快，但一线程阻塞全进程阻塞
- 内核线程：TCB 在内核空间，内核调度 → 互不影响，但切换慢

### Q6：多线程进程中，每个线程的栈是独立的吗？

**是的。** 每个线程有自己的栈（放局部变量和函数调用帧）。代码、数据、堆是所有线程共享的。

### Q7：线程切换为什么比进程切换快？

线程切换不改 CR3（页表基址），因为同进程的线程共享地址空间。进程切换要换页表 → 可能引发 TLB 全部刷新 → 慢很多。
