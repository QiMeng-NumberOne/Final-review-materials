## 1. 概述：操作系统的四种内存管理方式

> ⚠️ **重要澄清：连续 vs 非连续**
>
> 这四种方式中，**只有重定位是纯连续分配**。分段和分页本质上是**非连续内存分配**——它们正是为了解决连续分配的碎片问题才出现的：
>
> | 方式 | 连续性判断 |
> |------|----------|
> | **重定位** | 整个进程一块连续区域 → **连续** |
> | **分段** | 段与段之间可以分散放置 → **非连续**（但每段内部连续） |
> | **分页** | 页可以完全散落在物理内存各处 → **完全非连续** |
> | **虚拟内存** | 基于分页 → **非连续** |
>
> **Lec5 之所以把它们放在开头**，是作为内存管理方式的概述/演进脉络。本章真正展开讲的"连续内存分配"是指重定位 + 动态分区 + 伙伴系统这套方案。分段和分页的非连续分配细节在后续章节（Lec6、Lec7）中展开。

### 1.1 四种管理方式

操作系统采用的内存管理方式共有四种，按演进顺序：

| 序号 | 方式 | 核心思想 |
|:---:|------|---------|
| ① | **重定位（Relocation）** | 整个进程加一个基址偏移量，整体平移到物理内存 |
| ② | **分段（Segmentation）** | 按逻辑单元（代码段、数据段、堆、栈）分块，各放一处 |
| ③ | **分页（Paging）** | 逻辑空间和物理内存都切成固定大小的页，任意映射 |
| ④ | **虚拟内存（Virtual Memory）** | 分页 + 按需加载 + 缺页换入换出，逻辑空间可大于物理内存 |

> ⭐ **目前多数系统（如 Linux）采用按需页式虚拟内存。**
>
> ⭐ **实现高度依赖硬件，与计算机存储架构紧耦合。**

### 1.2 概念分层：机制 vs 策略

PPT 讲了两个层面的概念，它们配合使用而非并列：

```
┌──────────────────────────────────────────┐
│  机制层：地址怎么映射？                      │
│  重定位 / 分段 / 分页 / 虚拟内存            │
└──────────────────────────────────────────┘
                    +
┌──────────────────────────────────────────┐
│  策略层：物理内存怎么切分？                  │
│  静态分区 → 动态分区 → 伙伴系统            │
└──────────────────────────────────────────┘

例如：重定位 + 动态分区 = 早期系统
      分页 + 伙伴系统 = 现代操作系统
```

## 2. 计算机体系结构与内存层次

### 2.1 内存层次结构

```
┌─────────────────────────────────────────────────────┐
│  CPU                                                 │
│  ┌────────┐   ┌────────┐   ┌──────────────┐        │
│  │  ALU   │ → │  MMU   │ → │  控制逻辑     │        │
│  │ 运算器  │   │ 地址转换│   │ 总线读写请求   │──→ 总线 │
│  └────────┘   └────────┘   └──────────────┘        │
└─────────────────────────────────────────────────────┘
```

| 层次 | 速度 | 管理方 | 说明 |
|------|------|--------|------|
| CPU 寄存器 | 3.6GHz（最快） | 硬件 | ALU 直接操作 |
| L1 缓存 | 极快 | 硬件 | 命中时几乎无延迟 |
| L2 缓存 | 快 | 硬件 | 未命中则访问内存 |
| 内存（主存） | 1.3GHz | **操作系统** | MMU 管理地址转换 |
| 外存（磁盘） | ~5ms 寻道时间（慢） | **操作系统** | 虚拟内存的存储后端 |

### 2.2 重要硬件组件

#### ALU（算术逻辑单元）

- **定义**：CPU 内部执行运算的硬件组件
- **功能**：加、减、乘、除、与、或、非、异或、移位、比较
- **在内存访问中的角色**：计算出操作数的**逻辑地址**，交给 MMU 翻译

#### MMU（内存管理单元）

- **定义**：CPU 内部处理存储访问请求的硬件
- **核心功能**：
  1. **地址转换**：逻辑地址 → 物理地址
  2. **内存保护**：检查访问是否越界
  3. **权限检查**：控制读/写/执行权限
- **工作流程**：

```
CPU ALU 产生逻辑地址
       ↓
MMU 查页表/TLB 进行 逻辑地址 → 物理地址 转换
       ↓
MMU 检查越界？权限？
       ↓
CPU 控制逻辑向总线发出物理地址请求
       ↓
内存返回数据 / 写入数据
```

> ⭐ **MMU 是硬件，不是软件。** 它是操作系统实现虚拟内存、进程隔离、内存保护的**硬件基础**。没有 MMU，现代虚拟内存机制无法工作。

## 3. 地址空间与地址生成

### 3.1 两种地址空间

| 概念 | 范围 | 含义 | 类比 |
|------|------|------|------|
| **物理地址空间** | 0 → MAX~sys~ | 硬件实际安装的物理内存范围（内存条容量决定） | 真实世界 |
| **逻辑地址空间** | 0 → MAX~prog~ | 每个进程自己"以为"拥有的地址范围（OS 虚拟出来的） | 幻想世界 |

```
物理内存（唯一一份）              各进程的逻辑空间（各自独立）
0 ┌──────────┐                   进程P1: 0 ───── MAXprog
  │  内核    │                   进程P2: 0 ───── MAXprog
  ├──────────┤                   进程P3: 0 ───── MAXprog
  │ 进程P1   │                        ↑
  │ 进程P3   │                   每个进程都觉得自己
  │ 进程P2   │                   独占从0到MAXprog的全部内存
  └──────────┘ MAXsys
```

> ⭐ 逻辑空间可以比物理空间大（如 32 位系统进程拥有 4GB 逻辑空间，但物理内存可能只有 512MB）。这靠虚拟内存实现——正在用的映射到物理内存，暂时不用的存在磁盘上，用到时再换入。

### 3.2 地址从哪来？—— 逻辑地址生成全过程

```
源代码(.c)   →  编译  →  汇编代码(.s)  →  汇编  →  目标文件(.o)
                                                      ↓
                                                  链接（含库函数）
                                                      ↓
                                              可执行文件(ELF)
                                                      ↓
                                              exec() 加载执行
```

**三个阶段：**

| 阶段 | 逻辑地址确定方式 |
|------|----------------|
| **编译时** | 假设起始地址已知（如已知则直接生成绝对地址） |
| **加载时** | 编译器生成**可重定位代码**（relocatable code），加载时根据实际起始位置计算绝对地址 |
| **执行时** | 代码可在内存中移动，需要硬件地址转换（MMU）支持 |

### 3.3 地址映射与检查

```
                    ┌──────────────┐
逻辑地址 ──────────→ │ 段基址寄存器   │
                    │  + 逻辑地址    │
                    └──────┬───────┘
                           ↓
                    ┌──────────────┐
                    │ 段长度寄存器   │ ← 检查：是否 < limit？
                    │ limit 比较    │
                    └──────┬───────┘
                           ↓
                  ┌────────┴────────┐
                  │ 合法 → 物理地址   │  越界 → 内存异常 💀
                  └─────────────────┘
```

> ⭐ 每个进程的逻辑地址空间由操作系统通过 **base（起始）** 和 **limit（最大）** 两个寄存器限制，MMU 每次访存都会做越界检查。

### 3.4 为什么不同进程的逻辑地址可以一样？

**每个进程有独立的页表（或段表），翻译到不同的物理地址。**

```
进程A: 逻辑地址 0x401000 → 查页表A → 物理帧#7
进程B: 逻辑地址 0x401000 → 查页表B → 物理帧#99

CPU 通过 CR3 寄存器（x86）切换页表：
  进程切换 = CR3 切换 = 页表切换 = 同一逻辑地址走到不同物理位置
```

甚至可以**共享**：两个进程的同一个逻辑页（如 libc.so 的只读代码页）映射到**同一个物理帧**，省内存。

## 4. 连续内存分配

### 4.1 基本概念

> **连续内存分配**：给进程分配一块 **不小于指定大小** 且 **地址连续** 的物理内存区域。

### 4.2 内存碎片

```
┌──────────────────────────────────────────────────┐
│  分配单元A  │ 🕳 空洞 │ 分配单元B │ 🕳 空洞 │ 分配单元C │
└──────────────────────────────────────────────────┘
       ↑          ↑                    ↑
    已分配     外部碎片              已分配

内部碎片 = 分配单元 内部 没用完的空间（取整导致）
外部碎片 = 分配单元 之间 无法使用的空隙
```

| 碎片类型 | 位置 | 成因 |
|----------|------|------|
| **外部碎片** | 分配单元**之间** | 各分区大小不一，释放后留下大小不匹配的空隙 |
| **内部碎片** | 分配单元**内部** | 分配大小需要取整，多分配的部分用不上 |

### 4.3 什么是"物理连续"？

> 物理连续 = 在物理内存中地址是依次相邻的，不中断。

**为什么重定位需要物理连续？**

重定位只有**一个** base 寄存器：`物理地址 = 逻辑地址 + base`

```
逻辑地址 500 和 501 只差 1 → 加上同一 base → 物理地址也只差 1
→ 逻辑相邻 = 物理必然相邻 = 整个进程必须放在一块连续物理区域
```

**为什么分段也需要物理连续？**

每个段内也只有一个 base：段内的逻辑地址相邻必然导致物理地址相邻。但段与段之间可以分散（这是分段的进步）。

**为什么分页不需要物理连续？**

页表可以任意映射：页0→帧7，页1→帧2，页3→帧99... 逻辑页号之间没有数学上的相邻约束。

## 5. 动态分区分配与三种策略

### 5.1 静态分区 vs 动态分区

| | 静态分区 | 动态分区 |
|------|---------|---------|
| 分区大小 | 系统启动时**预先固定** | 运行时**按需决定** |
| 分区数量 | 固定 | 可变 |
| 内部碎片 | **严重**（分多了浪费） | 几乎没有 |
| 外部碎片 | 无 | **有**（时间久了产生） |
| 灵活性 | 差 | 好 |

### 5.2 动态分区分配

> 当程序被加载执行时，分配一个进程指定大小**可变**的分区（块/内存块），分区地址是连续的。

**操作系统需维护的数据结构：**

1. **所有进程的已分配分区**：记录每个占用块的起始地址和大小
2. **空闲分区列表（Empty-blocks）**：记录每块空闲区域的起始地址和大小

### 5.3 三种分配策略

#### 最先匹配（First Fit）

```
原理：从头开始搜索空闲列表，使用 第一个 ≥ 请求大小 的空闲块
列表排序：按 地址顺序

优点：实现简单；高地址空间保留大块空闲分区
缺点：产生外部碎片；分配大块时搜索较慢
```

#### 最佳匹配（Best Fit）

```
原理：在所有空闲块中，找一个 ≥ 请求大小 且 最小 的
列表排序：按 大小排序

优点：大部分分配较小时效果好；避免大空闲分区被拆分
缺点：释放分区较慢；容易产生很多无用的小碎片
```

#### 最差匹配（Worst Fit）

```
原理：在所有空闲块中，选 ≥ 请求大小 且 最大 的那个
列表排序：按 由大到小 排序

优点：避免太多小碎片；中等大小分配较多时效果好
缺点：释放分区较慢；破坏大空闲分区后，后续难以分配大分区
```

**三种策略对比：**

| | 最先匹配 | 最佳匹配 | 最差匹配 |
|------|:---:|:---:|:---:|
| 空闲列表排序 | 地址顺序 | 从小到大 | 从大到小 |
| 选择策略 | 第一个可用的 | 最小的够用的 | 最大的够用的 |
| 外部碎片 | 较多 | 多（小碎片多） | 少 |
| 大分区保护 | 好 | 好 | 差 |
| 分配速度 | 快 | 较慢 | 较慢 |
| 释放速度 | 快 | 较慢 | 较慢 |

## 6. 碎片整理

> **为什么需要整理？** 总空闲空间足够，但因碎片分散导致大块分配失败。整理 = 把散的空闲空间拼成一大块。

### 6.1 紧凑（Compaction）

```
核心思想：移动已分配的分区，让所有进程挤到一边，空闲空间聚到另一边

整理前：                        整理后：
┌──────────┐                    ┌──────────┐
│  进程A   │                    │  进程A   │ ← 没动
├──────────┤                    ├──────────┤
│  🕳 空洞  │                    │  进程B   │ ← 上移
├──────────┤         →          ├──────────┤
│  进程B   │                    │  进程C   │ ← 上移
├──────────┤                    ├══════════┤
│  进程C   │                    │  大块     │
├──────────┤                    │  空闲     │ ← 全部连成一片
│  空闲    │                    │          │
└──────────┘                    └──────────┘

条件：所有应用程序必须支持 动态重定位（运行时能换 base）
代价：搬数据消耗 CPU；进程暂停；DMA 期间不能搬
```

### 6.2 分区对换（Swapping）

```
核心思想：把暂时不运行的等待进程 换出到磁盘，腾出物理内存空间

          内存（小）                    外存/磁盘（大）
    ┌─────────────┐              ┌───────────────┐
    │ P1（运行）   │              │               │
    │ P3（就绪）   │    换出       │  P2（等待I/O） │
    │ P4（就绪）   │─────────────→│  P5（等待I/O） │
    │             │              │               │
    │             │    换入       │               │
    │             │←─────────────│  P6（就绪）    │ ← 需要跑时换回来
    └─────────────┘              └───────────────┘

关键问题：换哪个进程？→ 选等待 I/O 的（反正也跑不了，不浪费 CPU）
代价：磁盘 IO 非常慢，但是比什么都分配不了强
```

### 6.3 两种方法对比

| | 紧凑 | 分区对换 |
|------|------|---------|
| 操作 | 内存内部搬进程 | 内存 ↔ 磁盘 |
| 对象 | 运行中的进程 | 等待中的进程 |
| 代价 | CPU 时间 | 磁盘 IO（更慢） |
| 需要 | 动态重定位 | 磁盘 swap 空间 |
| 效果 | 合并碎片成大块 | 释放出一整块连续空间 |

## 7. 伙伴系统（Buddy System）

### 7.1 为什么需要伙伴系统？

动态分区的三种策略各有缺陷，尤其是外部碎片问题。伙伴系统通过**限制分配大小必须是 2 的幂次**，简化分配和合并，减少碎片。

### 7.2 基本原理

```
规则：整个可分配分区大小为 2^U

分配时：
  - 若所需 s 满足 2^(i-1) < s ≤ 2^i，分配一块 2^i
  - 若只有更大的空闲块（2^(i+1)），则将其 二等分
  - 重复二等分直到得到合适的块

释放时：
  - 检查相邻的"伙伴"是否也空闲
  - 若空闲则 合并，得到更大的块
  - 持续合并直到不能合并为止
```

### 7.3 合并条件（三个必须同时满足）

1. **大小相同**：两个块都是 2^i
2. **地址相邻**：物理上紧挨着
3. **低地址块的起始地址是 2^(i+1) 的倍数**：保证它们是同一个大块二等分出来的

### 7.4 数据结构

空闲块按**大小**和**起始地址**组织成**二维数组**：

```
大小 2^0: [空闲块1] [空闲块2] ...
大小 2^1: [空闲块A] [空闲块B] ...
大小 2^2: [空闲块X] ...
...
大小 2^U: [整个大块]
```

### 7.5 分配过程

1. 由小到大在空闲块数组中找**最小**的可用空闲块
2. 若空闲块过大，对其进行**反复二等分**直到得到合适大小的块
3. 将剩余的一半放回空闲列表
4. 初始状态：只有一个大小为 2^U 的空闲块

### 7.6 伙伴系统评价

| 优点 | 缺点 |
|------|------|
| 分配/释放/合并逻辑简单 | 内部碎片（分配 2^i 但只需 s，且 s < 2^i） |
| 外部碎片大大减少 | 块大小限制严格 |
| 合并快速（O(1) 找伙伴） | 仅适用于特定场景 |

## 8. ucore 中的物理内存管理实现

### 8.1 通用物理内存管理器接口

```c
struct pmm_manager {
    const char *name;                               // 管理器名称
    void (*init)(void);                             // 初始化
    void (*init_memmap)(struct Page *base, size_t n); // 初始化空闲页映射
    struct Page *(*alloc_pages)(size_t order);       // 分配 2^order 个页
    void (*free_pages)(struct Page *base, size_t n); // 释放 n 个页
    size_t (*nr_free_pages)(void);                   // 查询空闲页数
    void (*check)(void);                             // 自检函数
};
```

接口统一后，不同分配策略（如伙伴、First Fit 等）只需实现这一套函数。

### 8.2 伙伴系统的注册

```c
const struct pmm_manager buddy_pmm_manager = {
    .name          = "buddy_pmm_manager",
    .init          = buddy_init,
    .init_memmap   = buddy_init_memmap,
    .alloc_pages   = buddy_alloc_pages,
    .free_pages    = buddy_free_pages,
    .nr_free_pages = buddy_nr_free_pages,
    .check         = buddy_check,
};
```

通过函数指针实现多态，ucore 可以切换不同的物理内存分配策略。

## 9. 常见问题 FAQ

### Q1：MMU 是硬件还是软件？

**硬件**，位于 CPU 内部。OS 利用它完成地址转换，但 OS 本身不执行转换。

### Q2：逻辑地址什么时候产生？

**链接时**就确定了（编译器+链接器写入 ELF 文件）。CPU 执行时只是发出这些地址。

### Q3：页表什么时候建立？地址映射什么时候建立？

- 页表结构在 **exec() 时创建**（全是"不存在"的空壳）
- 物理帧映射在**运行时第一次访问该页时（缺页处理）** 建立
- 这叫**按需分页（Demand Paging）**

### Q4：程序加载时是全部加载到内存吗？

**不是！** 只加载真正访问到的页。100MB 的程序可能只加载了 5MB 就能跑。

### Q5：不同进程的逻辑地址可以一样吗？

**可以。** 每个进程有独立页表，同一逻辑地址翻译到不同物理地址。

### Q6：为什么重定位必须连续存放？

因为只有一个 base 寄存器：`物理地址 = 逻辑地址 + base`。逻辑相邻必然物理相邻。

### Q7：分页为什么能消除外部碎片？

所有页/帧大小固定 4KB，不存在"大小不匹配放不了"的问题。任何空闲帧都能容纳任何页面。

### Q8：分段有什么优于重定位的地方？

- 段与段之间**不需要物理连续**，可以分散放置
- 可按段设置不同权限（代码只读、数据可读写）
- 段间可共享（两个进程共用一个代码段）
- 分段的连续要求 = 段**内部**连续，而非整个进程

### Q9：分段和分页不是非连续分配吗？为什么放在"连续内存分配"这一章？

**分段和分页确实是非连续内存分配**。Lec5 在开头列出四种管理方式是作为**概述和演进脉络**，本章真正展开讲的是**连续分配方案**（重定位 + 动态分区 + 伙伴系统）。分段和分页的非连续分配细节在后续 Lec6、Lec7 中展开。
